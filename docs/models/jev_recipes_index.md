### Group 1: the named models

#### Jev (TypeSafe AI), closed
- Base: undisclosed. Reverse-engineering essay (archerhume.com, "Jev's Architecture Unmasked") hypothesizes a causal sparse-MoE decoder with ~10B active params [UNVERIFIED, inference from latency].
- Readout: two designs fit the evidence, a final-position head (255-option cap suggests slots) or a pointer-style scorer; behavioral tests show an option's score depends on the other options (irrelevant options shift log-odds by -0.28), i.e. options are read jointly by the decision position.
- Encoding: shared state prefix + per-question suffix with block-causal masking (a code placed in a sibling question is invisible, 0.00; in shared state 0.90-0.92). Option boundaries "cannot be forged by text" => special delimiter tokens.
- Loss: RLCD ("Reinforcement Learning for Calibrated Decisions"; proper scoring rules, Brier/log loss) [mechanism UNVERIFIED]; confidence field is a post-hoc formula (p_max - 1/K)/(1 - 1/K), not learned.
- Decision Index: Full 60.11 (rank 3), public 57.96; 266 ms median on its API.
- Images: Jev 1.13 text-only; "Jev Router" accepts media but returns text [per earlier notes].

#### Strands Decider 2B (AWS, `strands-labs/strands-decider`, HF `StrandsAgents/strands-decider-2B-hobson-v19`), open, Apache-2.0 -- primary source: repo docs/architecture.md
- Base: Qwen3.5-2B-Base (CN; v7 and earlier Qwen3-1.7B-Base). Not on the Decision Index table above (separate JevBench: v21 0.762 on 231 public items, ECE 0.064).
- Head: LM head discarded; **pointer readout (~1M params, dim 256, fp32)**: logit_k = <q(h_answer), k(h_option_k)>/sqrt(d); the query is the hidden state at the `<answer>` token and the keys are the hidden states at the **last token of each option's line**. No per-option parameters => no option ceiling, labels defined by the request, "same weights answer a 2-way yes/no and a 30-option routing question with unseen label sets".
- Encoding: XML-ish prompt (`<state>`, `<question type="choice">`, numbered `<options>` list, `<answer>`); options in-context; causal attention; question prompts are separate (shared-prefix KV fork, also for hybrid Gated-DeltaNet layers). Reversing option order moves the distribution by ~0.016.
- Multi-select: none (single masked softmax; choice, noul = 2-way, score = ordered 2-10 levels).
- Loss: CE on gold, with 10% of a `score` target mass moved to neighbouring levels (ordinal smoothing); **KL to the frozen torso's own readout** (weight 0.3; adapter-disabled model reading option-number tokens; anti-forgetting); **KL to a frozen teacher (Qwen3.5-4B read untrained, weight 1.0) only on multi-step rows where the teacher is measurably better**. Option order re-shuffled per example/epoch with label remapped ("one detail matters more than any of the loss terms").
- Data (v14): 100,449 rows from 21 public classification tasks + 12,909 multi-step rows (ContractNLI, MuSiQue, BoardgameQA); v19 adds 3,815 LLM-generated document questions and 6,166 answer-adequacy rows (HelpSteer2). All sources + licences in data/sources.md; generators for synthetic items committed (OpenRouter/Bedrock clients).
- Adaptation: rank-16 LoRA on torso projections + head; **~11 h on one RTX 3090, 1 h 10 min on 8xH100 (FAST=1)**; checkpoint 88 MB. Scripts `training/recipe.sh all`, `training/run_recipe.sh all`.
- Calibration: temperature fitting on a held-out calib split (`evaluate.py`); confidence derived, not predicted.
- Images: docs/vision.md; v21 answers over images "with no image training", ECE 0.014.
- Preregistration practice (research/preregistrations/PREREGISTRATION-v9..v20.md) is a useful model for our own experiments.

#### Cloudflare Clef (27B) / Clef-flash (9B), HF `Cloudflare/clef`, Apache-2.0 (weights + `joint_schema_model.py`, no training code)
- Base: Qwen3.8-27B / Qwen3.5-9B with their vision encoders (CN). Decision Index 0.3: Clef 53.08 (rank 19; public 61.71 but private-new-domain only 41.88 -- **public/private gap = overfitting to public benchmarks**); clef-flash 47.61. Vision board: not listed.
- Head: "joint schema head" -- a small transformer that reads backbone final hidden states, **routes evidence from the state to each question (cross-attention), then scores all options of all questions jointly** (field-to-field cross-attention, then back to the payload). One forward pass. Output: one logit per allowed option per question.
- Training (Cloudflare blog): backbone **frozen** + routing head jointly trained with **rank-256 LoRA**; losses **label-smoothed CE for valid schema outputs + Brier loss** for calibration; RLCD mentioned as a secondary target; data = "internal synthetic datasets permuting field orders, prompts and schema structures" (size undisclosed). Max input 16,384 tokens by default.
- Images/video: yes, native via the Qwen vision processor (`images`, `videos` in the record). Option encoding: question `criteria` dict (option id -> description) in-context.
- Why it matters: the only open model with a *multi-question joint head* (answers to several fields conditioned on each other).

#### Perplexity pplx-decider-v1 / v1.1 27B, HF `perplexity-ai/pplx-decider-v1.1-27b`, Apache-2.0 (card says "private repository" access in usage text)
- Base: Qwen3.8-27B (CN), **full fine-tune**; rank 1 on the Decision Index 0.3 (Full 62.75, public 62.25, private-new 55.57); on the vision board 63.20 (rank 4) with calibration ECE 0.0496.
- Head: native decision checkpoint = `Qwen3_5Model` backbone + `readout.safetensors` BF16 **[255, 5120] decision head** (a slot readout, not a pointer; one row per option position, up to 255), saved calibration temperature applied once.
- **v1.1 key change: "lifting of the causal mask"** -- the full-attention layers run in **non-causal (bidirectional) mode** at inference (linear-attention layers unchanged); plus more data, including **tasksource** (Sileo 2024, many converted NLP tasks) -- "a large part of the gains".
- Images: yes (inference.py takes `images=[...]`; the vision-board caveat says the checkpoint's own decision model accepts images).
- Not released: training data/scripts. Score trend: v1 56.4 -> v1.1 61.56 (Perplexity's own run).

#### IFM K2-Type-0.9B, HF `IFM/K2-Type-0.9B`, Apache-2.0 (weights + serving code; training code and data not released)
- Base: IFM/K2-Horizon-0.9B (MBZUAI Institute of Foundation Models, UAE; own architecture `K2HorizonForCausalLM`, 64,256 vocab, 28 layers, 8K -> 128K context, multi-teacher on-policy distillation; **appears to be an independent pretrain, not Qwen-derived [UNVERIFIED]**; card tags `en, zh`). Text-only. K2-Horizon family also has 3.7B (524K context), 7B, 32B text models.
- Head: **pointer head** (`pointer_head.safetensors`) scoring each option's `</opt>` hidden state against the question's `<decide>` hidden state; softmax at temperature 1.478. Input layout `<state> ... | <q> question <opt> option </opt> ... <decide> | <q> ...` with **five reserved tokens**; **block-causal mask** so questions share the state but cannot see each other.
- Options: 1-255 (choice), 2-255 ordered levels (score), noul = 2.
- Training: full FT on **~354k decision records** (public classification/NLI/QA sets, Kev's decision data, game positions with exact/search labels, synthetic items written and blind-verified by a large LLM); targets **mixed with soft labels from a 7B teacher decision model**; **50 PPO iterations on Snake** (RL for decisions); **temperature refit on held-out calibration data**. Decontaminated against Kev suites + JevBench public.
- Result: JevBench public 0.762, Brier 0.328, ECE 0.065, p50 27 ms. Not on the Decision Index table.

#### GLiDE (Fastino), closed API ("open weights coming soon"), 28B, "full fine-tune, autoregressive"
- Board: rank 2, Full 60.21 (public 59.06, private-same 59.49, new 52.87), calibration acc 0.749, ECE 0.040, Brier 0.340, median 98 ms. Base undisclosed (27.8B => almost certainly Qwen3.x-27B [UNVERIFIED]).
- Fastino's blog (fetched): "thinking decision model": returns a fast distribution, then **allocates additional reasoning only when the leading option is uncertain**; 40k context; hundreds of options. Training data, losses, base: not disclosed. Same idea as AutoTrust's GEV adaptive thinking (below).

#### CLM-v0.1-8B (Stanford + NVIDIA, `Contrastive-LM/CLM-v0.1-8B`, code `github.com/Contrastive-LM/CLM`), Apache-2.0
- Base: frozen Qwen3-8B(-Base) used as an **embedding encoder** (last-token pooled embeddings); trained: two small projection heads (state head, action head).
- Objective: **bidirectional InfoNCE** between state embedding and action (option) embeddings; pretrain ~60M Nemotron Q&A pairs, mid-train ~30M synthetic hard negatives, post-train ~1M agentic trajectories. Options are encoded **separately** from the state -> action embeddings cacheable (13x faster than Jev with ~1k candidates). Verifier fine-tuning only trains heads: `python train/finetune.py --task clm --init-ckpt ... --batch 512`.
- **Decision Index: Full 6.24 (rank 101 of 112), calibration ECE 0.32, Brier 0.90** -- zero-shot typed questions with free-text option descriptions are poor for a contrastive model; it is good only after head fine-tuning on a target task. No images. A multimodal CLM-35B-A3B was announced (not found on the board).
- Takeaway: for a *closed* label set the contrastive recipe works only with in-domain head training; as a zero-shot Jev replacement it fails the benchmark.

### Group 2: Kev lineage and small LoRA + pointer-head models

#### Kev (Jared Palmer; github.com/jaredpalmer/kev; HF `jaredpalmer/kev-{0.8b,4b,9b,27b}`) -- the reference open recipe; Apache-2.0
- Base: Qwen3.5/3.8 (CN) but the *method* is base-agnostic: **rank-16 LoRA + pointer head on a frozen base**; Kev-27B = full fine-tune (8xH200, 1 epoch, lr 2e-6, 145,840 records, states up to 32,768 tokens) weight-averaged 0.85/0.15 with the earlier adapter model. Board: Kev 27B Full 58.78 (rank 6; public 56.69, private-new 55.49: the **smallest public/private gap in the top 10**); 9B 43.27; 4B 39.5; 0.8B 13.66.
- Format: `<state> ... <q> instructions <opt> option 1 </opt> <opt> option 2 </opt> ... <decide>`; pointer head scores each `</opt>` hidden state against the `<decide>` state; on hybrid (DeltaNet) bases each question is its own row (state + one question) with shared-prefix cache; on attention-only bases a **block-causal attention mask with position ids restarting after the state** gives exact question isolation. Delimiter-like strings in user text are escaped (`split_special_tokens`).
- Loss: plain CE on the correct option (soft targets where given); optional `--perm_kl` (consistency across option orders) and `--ord_w` (ordinal) exist but were NOT used in the release; augmentation: option shuffle, `--p_none_pair 0.25` ("none of the above" pairs), irrelevant distractors, minimal pairs.
- Data: `decision-v7` = 10,000 examples from 10 public datasets + 896 generated policy examples + 1,680 from 60 generated rule structures; lr 1e-4 (0.8B) / 5e-5 (4B, 9B), 2 epochs, ~20 min (0.8B) to ~1 h (4B) on one H100. Then short `--init_from` follow-up fine-tunes (day-count cases, evidence-removed cases, real documents). **Fine-tune lesson: starting from base lost the general skill (0.33 vs 0.84); `--init_from` the released checkpoint kept 0.83 and reached 0.88 on the new domain.**
- Calibration: single fitted temperature per checkpoint (2.41 for 4B, 1.32 for 27B).
- Images: none. `kev-finetune` agent skill (Modal) automates label conversion, training, temperature fit, deploy.

#### Jevstral 8B (AmirBraham/jevstral, `mistralai/Ministral-3-8B-Base-2512`, US/EU-compatible, Apache-2.0) -- Kev ported to Mistral
- LoRA adapter + delimiter-token rows + pointer head (`head.pt`) + one temperature (T = 2.04). Per-question row `<s> <state> ... <q> instr <opt> o1 </opt> ... <decide>`. 4 stages on one H100 (~70 + 10 + 45 + 80 min); CE with soft targets; augmentation: option shuffle, none-of-the-above, irrelevant distractors, minimal pairs; data = `jaredpalmer/kev-suites` public decision suites (SHA-pinned). Board Full 35.93 (rank 63), 28 ms. **Shows the pointer-head recipe transfers to a non-Chinese base, but a small-data LoRA on a base model scores low on the broad index** (it was trained on narrow in-distribution suites). Text only as used (the `mistral3` Ministral-3 family is probably multimodal [UNVERIFIED]; the vision tower is not used).

#### Lev1-3.7B (theaviv; `IFM/K2-Horizon-3.7B` base; Apache-2.0)
- LoRA rank 32/alpha 64 on a 163,611-question mixture; each short question also appears in a second option order with a **consistency loss**; for 15,591 questions the target **blends gold with Gemma-4-31B-it's probabilities** (only on sources where Gemma matched gold >= 60%); some items written by MiMo-V2.6-Flash (Xiaomi; a Chinese model used as *data writer*, flag for contamination policy). Synthetic part public (`theaviv/lev1-decisions`). Board Full 38.63 (rank 55), best-in-class on Tools. Text only.

#### EXAONE-4.0-1.2B-JEV (carrtesy; LG AI Research EXAONE, KR; **license: EXAONE NC, research only**)
- Full fine-tune 227,529 rows (commonsense MC, BANKING77/CLINC150 many-option intents, detection, NLI, ToolACE, When2Call), 1 epoch, lr 2e-5; **letter readout**: answer = softmax over the A..X label token logits at the answer position; loss = full-vocab CE on the label + EOS; **two option orders averaged ("permute: 2")**; temperatures per type (noul / 2-option / 3-5 / 6+); choice > 24 options read in chunks + final read over chunk leaders. Board Full 23.31 (rank 79), 148 ms. Useful as the cleanest write-up of the letter-readout recipe.

### Group 3: letter-readout models on Gemma 4 (non-Chinese, several multimodal) and the "stock model" result

**Headline finding of the whole index: a stock, un-fine-tuned Gemma 4 read through a letter readout + one calibration temperature is already near the top.** `deck31b` (frozen `gemma-4-31B-it`, FP8, no training; T = 3.4 taken from the public Cygnet recipe) is rank 5 of 112 (Full 59.03); `decider-chat-gemma4-31b` (stock Gemma-4-31B + config) is rank 9 (57.62); on the official JevBench v1.5.4 board **"Cygnet" = frozen `gemma-4-12B-it`, unmodified vLLM, no fine-tuning, is No. 1 of 106 (73.70, statistical tie with the Gemma-4-12B LoRA Winnow-12B Q8 73.23 and ahead of Jev 72.13)**. Mapika's README: "On the index the base model sets most of the score: our trained 35B, 4B and 2B are below these two stock models read the same way." The best open models on the index are all <=31B dense/MoE chat models with a letter readout.

#### Cygnet recipe (blockbrain-ai/cygnet-recipe, MIT) and deck31b (github.com/krishna-gogineni-765/deck31b, Apache-2.0 server)
- Base: **frozen `google/gemma-4-12B-it` / `gemma-4-31B-it`** (US, Apache-2.0 Gemma 4). No training.
- Readout: chat prompt with state, instructions and options lettered A, B, C...; vLLM masks the answer position to the option letters (`structured_outputs.choice`), requests top-20 logprobs; **sum the probability of EVERY vocabulary token that decodes to each letter** (Gemma-4 has several tokens per letter, e.g. "A" and " A"; dict-keying drops mass), renormalize over the options, then p^(1/T) with **T = 3.4** fitted by NLL on 241 self-generated items (T = 3.1 when fitted on half of the public items; ECE 0.140 -> 0.101 on the held-out half). Up to 26 options in one pass (two-letter codes after Z in other implementations).
- Gemma-4 specific gotcha (Mapika decider 1.7.0): apply Gemma's final-logit softcapping to the letter logits or the distribution is read too sharply. Also (Blink): keep thinking off, with thinking on a third of the answers never close the thought.
- Multi-label: none. Images: Gemma 4 12B/31B have a vision tower; Cygnet's JevBench run is text, but the same letter readout works with images in the chat turn (see Winnow and AutoTrust below).

#### Mapika `decider-chat-gemma4-31b` and `decider-12b` (github.com/Mapika/decider; Apache-2.0)
- Stock Gemma-4-31B or 12B-it + `decider_config.json`: `temperature_by_options` T(n) = max(Tmin, a + b ln n) as a function of the number of options (the v1.8.0 trick: **option-count-dependent temperature**), per-type temperatures (12B v1: Choice 4.0, Noul 1.0, Score 3.5). `decider-12b` v2 = rank-32 LoRA on 6,000 generated state-tracking decisions + 4,000 replayed rows; v2 then used T: Choice 1.5, Noul 0.05, Score 1.0 -- i.e. **a light LoRA moves the optimal temperature from ~4 to ~1.5, calibration is part of the recipe**, and accuracy gains from the LoRA were small on hard items (0.730 -> 0.712 JevBench-hard).
- Mapika's own trained decider-2b/4b/35B-A3B (Qwen bases) use the shared-prefix per-question rows with a pointer-style readout and a "teacher_data" mix labelled by a local Qwen3.5-27B teacher (public datasets + 26 more public decision sets + 10 programmatic families with verifiable gold).

#### Winnow-12B / Winnow-E4B (EldanRing; `gemma-4-12B-it`, `gemma-4-E4B`; Apache-2.0; GGUF only) -- vision-capable
- Rank-32/alpha-64 LoRA (attention + MLP projections), zero dropout, merged; private data = synthetic scenarios + teacher-supervised examples + labeled semantic tasks (routing, rule application, evidence selection, ordinal judgments, entailment, answerability); decision temperature 1.0. Letter scoring through llama.cpp `/v1/systemone`; image input through an F16 mmproj (vision tower unchanged). Board Full 49.27 (rank 26), vision-board Full 59.84 (rank 6; caveat: base answers at chance through the converted projector); JevBench public 85.28-85.71% ties Jev. Optional "adaptive reasoning" (generate then re-score) gave +1.6 pp (CI -2.3..+5.5) at 4x latency: not worth it.

#### AJev (andyzhang232; `gemma-4-12B-it` LoRA r32/a64; also a 26B-A4B version; Apache-2.0; training code private)
- Per-question chat prompt with a fixed instruction line + question-type hint + options lettered A.. (single-token two-letter codes after Z, up to 255 options); the bare and space-prefixed letter tokens' logits combined; per-question-type temperature fitted on held-out data. **Objective: CE on label logits (label smoothing 0.05) + a ranked-probability term for `score` + a consistency term between option orders.** Data 64,819 decisions, 1 epoch, public classification/NLI/preference/safety sets (EN + ZH) + generated business-rule cases; **decontamination against the benchmark (508 items removed)**. LR 3e-5 cosine, 32 decisions/step, states up to 16K tokens, **one RTX PRO 6000 (96 GB), ~13 h**. Calibration: zero-shot ECE 0.280 -> 0.142 (typed decisions), 0.204 -> 0.060 (Kev v9). Board Full 50.02 (rank 25).

#### Hopper 12B (HopitAI; Gemma-4-12B-it LoRA, Apache-2.0; code github.com/hopit-ai/hopper) and Hopper-G (Qwen 4B)
- Qwen3.5-4B version: rank-16 LoRA; system prompt "Reply with the letter of the correct option"; user JSON {"evidence","criterion","options":[{"letter","description"}]}; softmax over the option letters' next-token logits + per-answer-type temperature (choice 0.790, noul 0.753, score 0.900); **ablation showed a bounded linear calibration map (option count, state length, entropy) was worth only +0.1 over no map on unseen sources vs +4.5/+2.9 for a simple per-type temperature** -> use per-type temperature. Training data = LLM-generated decision families (labels computed in code), a JevBench-style LLM-generated set kept only where independent LLM solvers agree, and public human-labelled sets (ARC, CSQA, MMLU aux, SNLI, MNLI, VitaminC, BoolQ, SQuAD2, CLINC, DBpedia, HelpSteer2). Detailed disclosure of dev-gating (26 configurations on 115 items) -- a good example of how to avoid overfitting a tiny dev set.

#### Xor 26B-A4B (Juspay; Gemma-4-26B-A4B-it; Apache-2.0)
- **Model soup**: two LoRA lineages (A: attention + dense MLP r32/a64; B: same + router + all 128 experts with tiered ranks 16/8/4 by routing frequency), merged and weight-averaged 0.5/0.5, then pulled 15% back toward the base (W = 0.85 W_soup + 0.15 W_base). Vision tower untouched but the API rejects images. Letter logprob softmax at T = 1.95 for choice, 1.0 for noul/score; text only. Board Full 55.95 (rank 12). Xor 1.2 (Qwen3.6-35B-A3B LoRA) tops the vision board at 64.30 with tight calibration (ECE 0.0084).

#### GEV-26B-Decide / JEV-27B-VL / JEV-9B (AutoTrust AI Lab; Gemma-4-26B-A4B-it LoRA; Qwen-based JEV-27B/9B)
- GEV (`base_model_relation: adapter`) = Gemma-4-26B-A4B-it + LoRA; letters A-P trained; `choice` 2-256 options, up to 16 read in one pass, >16 read as a **tournament** (groups of 16 in parallel, then a final of 16; CLINC150 95.2% vs 88.5% single pass with labels beyond P). **Adaptive thinking**: System 1 distribution p1; if top prob < 0.8, run Gemma thinking mode (budget 8,192 tokens), read the answer-letter distribution p2, final p = 0.5 p1 + 0.5 p2 (p2 alone is near one-hot and over-confident; the equal mix keeps accuracy and calibration). Threshold and mix chosen on 1,754 held-out questions; reaches 96% of the always-think gain while thinking on 48% of questions. Same idea as Fastino GLiDE.
- **Images: "the checkpoint contains Gemma-4's vision encoder; the decision head was trained on text; decisions over images are zero-shot."** Demos: computer-use element selection (95% of 60 tasks, ~85 ms/click) and robot-arm pick-and-place. Lesson from their report: System 1 is fine for simple visual questions in a control loop but asked to pick 1 of 8 motor commands directly, 0/10.

#### Quyet-1.0-Large (chinhnc; Gemma-4-31B-it, merged rank-16 LoRA; Apache-2.0), Surogate Rune (Gemma-4-26B-A4B full FT; `surogate` decisions v1 protocol: one question per prompt, thinking off, softmax over option-letter logits), Blink v0.3 (PixilabAI; Gemma-4-26B-A4B full fine-tune; NVFP4/FP8; letters up to 26 then two-letter codes; T = 1.3 shipped, v0.2 wanted 1.9; ECE 0.016 over 216,942 decisions), TorchCast, GEV: all use the same letter readout. Rune: board rank 10, Full 57.43; ECE 0.12 (worse calibrated than Blink). Quyet: up to 10 options, Vietnamese tuned.

#### Jev-Omni (akhilaaa3; `gemma-4-12B-it`, "merged"; Apache-2.0) -- the only Gemma decision model with image + audio + video input
- Classification head over Gemma 4 12B hidden states ("the head accepts 256 options; best <=20"), FP32 weights, BF16 autocast; **30,000-question fine-tuning run**; modalities handled by loading "the original Gemma 4 multimodal components automatically" (image tower, audio capped at 30 s, video 16 frames). Latency on H200: 26 ms (image), 83 ms (2k-token text). Board Full 42.35 (rank 44, vision-board 48.32 with a single-image-only caveat); JevBench 86.15%. Medium ECE 0.040. Dataset `akhilaaa3/decision-bench` public.

#### Gevva-E4B / E2B (davidburhans; `gemma-4-E4B-it`, `E2B-it`; Apache-2.0) -- a cross-encoder classification head, not a Jev readout
- Last-token pooled representation -> Gemma4RMSNorm -> **3-class linear head** (contradiction/entailment/neutral); options are ranked by running a pair (premise, option) through the NLI head ("rerank"), **strictly proper Brier-score training, ECE 0.0224**; 128K context, multimodal. Board Full 33.02 (rank 67, text-only path). Shows that a per-option NLI-style cross-encoder scales linearly in the number of options (one forward per option) but works with any base; fine for our 11-100 option fields only if the image is cached.

### Other vision-capable entrants (Chinese bases; recipes worth stealing)

#### RSI-Jev v5.0-VL 3B (shgao; `Qwen3.5-4B-Base` truncated at layer 20 of 32; Apache-2.0; github.com/Shanghua-Gao/RSI-Jev; built by "a self-improving loop of AI agents")
- Keeps only decoder layers 1-20 + final norm + the base's vision tower (frozen, shipped in the checkpoint; up to 4 images with `<image>` markers) + a 0.05B decision head. "The quality curve flattens by layer 20: reading at layer 20 scores like reading at layer 32 and costs 12 fewer layers per token." Option vector = **mean of the hidden states of the option's own block tokens, excluding the separator/key tokens that open it** (those carry the previous option in a causal model; pooling them made the model pick the option *after* the right one on long numbered lists); confidence head fitted post hoc.
- Three stages: (1) text SFT from base, 3,000 steps, batch 16, **311,118 questions over 68 sources, lower 8 layers at 1/10 LR, LM-retention term computed at the exit layer**; (2) images, 3,000 steps at half LR, **48,000 questions: 21,754 image questions (spatial relations, joint reasoning, recasts, sokoban) + 2,000 'unknown'-answer text rows + 24,246 text replay**; (3) head only, 600 steps, LR 1e-5 with the tower frozen. No RL. Held-out image set 0.829; vision-board Full 56.54 (rank 9) at 3.25B params.

#### JPT (kirp, `github.com/tic-top/llm2jev`; Qwen3.5 0.8B/4B/9B/35B-A3B; CC-BY-NC)
- LoRA merged into full weights, vision tower unchanged, **one epoch on 49,221 typed questions (`mix_train_env_v11`)**; letter readout through `llm2jev`, a generic wrapper that "turns any chat model into a Jev-compatible probability service" (state + question + all options in one prompt, shared prefix cached, images/video/audio in the state); single temperature T = 1.087 fitted once. **Images untested but go zero-shot through the base vision tower, and JPT-9B is #5 on the vision board (Full 61.87), JPT-4B #7 (59.65)** -- i.e. text-trained decision LoRA + vision tower generalize to images.

#### Solomon v1.1 (DoccyHealth; Qwen3.8-27B LoRA + trained linear answer heads) -- #1 on the vision board (67.66)
- Four answer types (boolean, **multilabel**, single, ordered). **Adapter off while the document is read, on from the question onward** (question-side LoRA placement); letter logits at a fixed commit position read through trained linear heads; **yes/no-shaped units, including each candidate of a multi-label answer, share one merged yes/no head** (p = sigmoid(log P(yes)/P(no) / T)); question-level multilabel score = product of per-candidate probabilities (admittedly an uncalibrated heuristic joint). Handles rendered page images; max 8 options on the vision board (more counts as failure). Only trains on synthetic documents + Qwen3.8-2.4T-labelled real documents (no Claude/GPT output by policy).

#### Intern-Decision 0.8B/2B/4B (internlm; full fine-tune on Qwen3.5-*-Base; github.com/internlm/Intern-Decision) and NeoHorse-Jev-4B (TokenRhythm; a Chinese NeoHorse-1-4B base; single image + text)
- Both appear on the vision board (Intern-Decision-4B Full 56.89; NeoHorse 50.73, "Takes a single image only"). Intern-Decision swaps the vision patch embed for an identical linear map for speed. NeoHorse reports Image-NLI 60.65% on 8,000 image-statement items and demos Doom/driving with images. Not transferable beyond "decision head works on a VLM with text-only training".

#### Intern-Decision (internlm/Intern-Decision; Qwen3.5 base, but fully documented training code) -- the cleanest "JSON skeleton, one pass, all fields" recipe
- Base: Qwen3.5 0.8B/2B/4B (CN; **recipe is base-agnostic**). Vision tower and projector **frozen**; language backbone **fully fine-tuned** (XTuner FSDP; `configs/training/qwen35.py`): AdamW lr 2e-6 (cosine to 2e-7, 3% warmup), wd 0.01, global batch 16, **2 epochs**, sample max length 8,192, packed.
- Format ("autoregressive masked language modeling"): the assistant turn contains a **complete JSON skeleton with one `<decision>` marker per field**; the logit immediately *before* each marker predicts that field's answer (ordinary causal next-token alignment). **All fields share one causal forward pass.** Options map to **62 single-token symbols (A-Z, a-z, 0-9)**; labels (gold symbols) appear only in the loss, never in the input; CE is over the **full vocabulary** at training, restricted to the legal symbols at inference, then softmax + checkpoint temperature (T = 1.99 for the 4B). Service limit 1-16 fields per request, option order is preserved and must be preserved. Question types: choice / score / noul (always ordered no, yes).
- Images: optional ordered image list through the Qwen3-VL processor (`max_pixels` default 16384*32*32); `visual_pack_weight=0.0` so image tokens do not count towards packing loss. Vision board: 4B Full 56.89 (rank 8), 2B 48.36, 0.8B 36.86. Calibration pilot (96 cases with exact reference distributions): Brier 0.550, ECE 0.089 vs Jev 0.595/0.130. No data released (the doc says so explicitly).

#### AutoTrust JEV-27B / JEV-9B (autotrust; Qwen base; "Blocks of Experts"; Apache-2.0) -- distillation from Jev 1.13 [ToS caveat]
- System-1 block = LoRA r=16 on decoder projections + **a 24-slot fp32 decision head initialised from the backbone's own `lm_head` rows for the verbalizer tokens (false/true, 0-5, A-P)** (so at step 0 the output equals the pretrained model's zero-shot restricted next-token distribution; |dp| < 1e-5; already 58% on choice, noul AUROC 0.88 before any labels). 108.9M trained params (0.4%), one cosine schedule of 5,000 steps, ~640k rows, **~9.2 B200-hours** for 27B. Targets = **Jev 1.13's published output distributions (KL distillation; `SargeDev/jev-distill-corpus-v3`)** across 53 training domains -- teacher is an API model (check its terms before copying), student reaches 96-98% of the teacher's accuracy on human-labelled held-out data.
- Serving: backbone stays pristine (adapter applied only on the decision path); **merging the LoRA into the backbone dropped HumanEval 70.7 -> 61.6 on the 9B** while prose perplexity barely moved -- a concrete forgetting number for our "one end-to-end VLM" goal. >16 options read as chunks ("wide-labels" / tournament). Board: JEV-27B Full 55.64 (rank 14), JEV-9B 45.21.

### Group 5: diffusion and inference-only "structured read"

#### DiffusionGemma-as-Jev (open-jev by JoshuaSP; djev (Davipar); vLLM PR #57250 (mmastrac/razorback); Prem API) -- no training, `google/diffusiongemma-26B-A4B-it` (Gemma 4 26B-A4B MoE diffusion; Apache-2.0)
- **Structured read**: the answer is a fixed JSON template whose answer slots are blanks; tokenize all allowed JSON documents; fix shared token positions, init the others with uniform full-vocab noise, run N (1-2) denoising steps on the 256-token canvas, then **at the final readout pick the highest-logit allowed token per slot** (for multi-token alternatives the first differing token discriminates, unique suffixes are forced); output is validated JSON with no repair. `FieldCanvas` compiles each field separately and packs all fields into one canvas without Cartesian enumeration. Multiple fields **share attention** (no isolation, accuracy can change). 2-step grouped inference is 4.85x faster / 79% cheaper than one-question-per-sequence with 296 vs 298 correct of 337.
- djev adds a typed layer with exact label-id probabilities (not top-k), compact canvases, and **image/camera inputs with native multimodal attention (option images can be carried into the same call)**. Prem API: one image (base64) or one <=30 s MP4 (<=4 sampled frames), up to 16 questions/request, 96 GB Blackwell, ~13 req/s, 440 ms p95; "probabilities are normalized model scores, not calibrated".
- Board: JoshuaSP 47.32 (rank 33, **ECE 0.2155**, Brier 0.524), djev 41.78, mmastrac 36.30; vision board 36.86 / 36.36 / 30.28. Uncalibrated and clearly behind letter readout on an AR Gemma. 25.8B params, 3.8B active: not a practical base for fine-tuning. The idea worth keeping is the **JSON-template structured read** (one pass, per-slot logits restricted to allowed tokens) which the AR models above also implement (Intern-Decision skeleton).

#### Parallel Constrained Decoding (LFM2.5-2.6B-RLCD, monotykamary; unchanged LiquidAI weights; Liquid license)
- Prefill the shared context once, **branch attention AND convolution/recurrent state per field**, evaluate allowed answers in parallel, serialize typed JSON in Python. "token" mode (opaque atomic option codes, verified against the tokenizer; output head projected only onto the option-token rows) was 9.9x faster than AR JSON (56 ms vs 557 ms) and 45.6x on a 28-boolean schema; but accuracy only 72.2% on 6 fresh audit cases vs 94.4% AR, failing high-cardinality probes. The "RLCD" name here does NOT mean the TypeSafe algorithm; **no open model on the board actually reproduces RLCD (RL with Brier rewards)**: K2-Type's 50 PPO steps on Snake and Clef's Brier loss are the closest. ### Observations from the Space itself (methodology)
- Score = chance-corrected skill; "an unanswered request counts as wrong"; "rows an entrant trained on count as wrong"; private tests nobody can train on get 80% of Full weight. Models tuned on public benchmarks drop sharply: **Clef public 61.71 -> private-new 41.88; Torchcast 65.10 -> 50.83; pplx 62.25 -> 55.57; Kev-27B 56.69 -> 55.49 (flat)**. Lesson for us: validate on held-out *datasets*, not held-out rows.
- Calibration across the board: ECE 0.014 (Jebadiah) to 0.57 (LFM-350M); best-calibrated high scorers: Jebadiah 27B 0.014, Kev-27B 0.022, Decider 35B-A3B 0.023, Clef-flash 0.025, Intern-Decision 4B 0.028; fine-tuned-and-merged Gemma models (Rune 0.12, Winnow 0.17, Jev-Omni 0.16) are worse calibrated than their Qwen counterparts, consistent with each needing its own fitted temperature (Gemma stock T ~ 3.4-4, after LoRA ~1.5).

## (d) Transferable-recipe shortlist for MMBU Pass-2

Task constraints: image in; six fields (modality 11, submodality ~37 child-of-modality, body part ~100 multi-label, stain ~40 microscopy-only, specimen ~37, domain 23 multi-label); target is one end-to-end VLM that emits JSON; a classifier is also a teacher/labeler and a way to adapt the vision tower. None of the 112 models is image-first or medical; the transferable value is the **format, the readout, the loss mix and the calibration procedure**. All recommended bases are non-Chinese: **Gemma 4 (E4B 4.5B, 12B, 26B-A4B, 31B; confirmed multimodal via HF API pipeline tags `any-to-any` / `image-text-to-text`, Apache-2.0)** is the only family with a deep bench of precedents here; Moondream 3.1, Molmo2-O, Ministral-3 and Phi have no Jev-style precedent in this index.

1. **Stock-model letter readout as the zero-training baseline and labeler (Cygnet / deck31b / Mapika decider-chat).** Copy: lettered options in the chat turn, thinking off, one answer position, **sum probability over every vocabulary token that decodes to each letter** (Gemma has several), apply Gemma's final-logit softcapping, renormalize over listed options, then temperature (T ~ 3.4 stock; use Mapika's T(n) = max(Tmin, a + b ln n) because our option counts range from 11 to 100). Onto: Gemma-4-12B-it / 31B-it with images in the user turn. Why first: frozen 12B is No. 1 of 106 on the official JevBench and a frozen 31B is rank 5 on the Decision Index, so the base VLM's zero-shot Pass-2 accuracy is the number to beat and its calibrated distributions are usable pseudo-label priors for unlabeled images. Limit: 26 letters (two-letter codes beyond), so body part (~100) needs the pointer alternative (item 3) or two-stage coarse-to-fine options.
2. **Intern-Decision JSON-skeleton training (single pass, all fields), full-FT language side, frozen vision tower, then optionally unfreeze.** Copy exactly: assistant turn = the JSON skeleton with one marker per field; loss on the marker positions only (CE over full vocab at training, restricted to legal symbols at inference); single-token option symbols; lr 2e-6 cosine, wd 0.01, batch 16, 2 epochs; gold labels never in the input. Onto: Gemma-4-12B (or E4B for speed) using the same masked-label collator (their code is `src/inputs/masked.py`; only the tokenizer/template needs swapping). Why: this is *the same format as the competition output* (JSON), reads six fields in one pass with probabilities for free, and its checkpoints are already 4B-class with calibrated T on a VLM. Note for hierarchy: all fields share a causal pass, so order the skeleton modality -> submodality -> body part -> stain -> specimen -> domain and train with gold earlier fields teacher-forced; at inference read each marker with the model's argmax of earlier fields (or prune the submodality symbol set to children of the predicted modality). This hierarchy handling is **our design, not found in any source**; Clef's joint head is the only precedent for conditioning fields on each other, and Kev/K2-Type deliberately isolate questions.
3. **Pointer head over in-context option labels (Strands / Kev / K2-Type), with a sigmoid variant for multi-label.** Copy: tiny (~1M-param, fp32) head scoring each option's last-token hidden state against the answer-position hidden state, no per-option parameters, option list re-shuffled every example/epoch with labels remapped, rank-16 LoRA on the torso, KL to the frozen torso's own readout (weight 0.3) as anti-forgetting. Onto: Gemma-4 (any size; Strands runs on a single RTX 3090 in ~11 h at 2B; Jevstral shows the recipe works on Ministral-3-8B). Why: removes the 26-letter limit (body part ~100, stain ~40), lets us add a label without retraining, and the block-causal / shared-prefix design means **the image is encoded once and every field is a cheap branch** (Kev, Strands `infer.py` prefix fork). For the two multi-label fields, replace the softmax with per-option logits + BCE (Solomon's merged yes/no head and GLiNER2's per-label thresholded classification are the precedents; Solomon's rolled-up product is flagged by its authors as an uncalibrated joint, so report per-label probabilities, not a joint). Add a "none/not applicable" option for stain (Kev `p_none_pair` 0.25, Strands v20 catch-all rows).
4. **Calibration protocol: per-field temperature fitted on held-out *datasets*, plus label-smoothed CE + Brier.** Copy: label smoothing 0.05 and an ordinal/ranked-probability term only where a field is ordinal (none of ours is), an option-order consistency term (AJev, Lev1) -- cheap with a pointer head; Brier loss (Clef, Von); a single temperature per field/type fitted by NLL on datasets *not used in training* (Kev 9B/27B: T = 2.19 / 1.32 fitted on held-out datasets; Hopper's ablation: the per-type temperature gave +4.5/+2.9 vs +0.1 for a fancy feature-based map on unseen sources). Expect T to shift by ~2.5x after LoRA (Mapika Gemma-12B stock 4.0 -> LoRA 1.5). Onto: whichever base; costs minutes. Why: Pass-2 labels come from 393 datasets with heterogeneous label noise, and the Space shows the biggest public-to-private drops (Clef -20, Torchcast -14, pplx -7) for models tuned on a public distribution while Kev-27B stayed flat.
5. **Forgetting control and recipe for keeping the VLM general (AutoTrust JEV-27B, Strands, RSI-Jev).** Copy: LoRA r16-32 on a pristine backbone (merged LoRA cost 9 points of HumanEval at 9B; keep the adapter separable or merge only after replay), initialize any new readout from the backbone's own `lm_head` rows for the symbol tokens (JEV-27B: zero-shot parity at step 0), replay text/VQA data (RSI-Jev: 24k text replay + LM-retention term at the exit layer), lower LR for lower layers (1/10 for the first 8 layers). Onto: Gemma-4-12B for the end-to-end submission. Why: the competition model must still produce JSON and answer other MMBU tasks. **Vision-tower adaptation (Track 3) has no precedent here**: Intern-Decision and RSI-Jev freeze the tower; JPT/GEV/Strands transfer text-only training zero-shot to images. If we unfreeze it, use the Pass-2 loss with a small tower LR and keep a frozen-tower arm as control.

Runner-ups considered and rejected: CLM contrastive (rank 101, ECE 0.32; only viable as head-trained retrieval); DiffusionGemma structured read (uncalibrated, 26B, no training path -- but its JSON-template idea is subsumed by item 2); encoder cross-encoders (Von / Bekko / GLiNER2: text only, but Von's per-option attention isolation + restarted position ids is the best order-invariance trick if option order proves a problem); distillation from Jev (AutoTrust; API-terms risk and no image support); adaptive thinking (GLiDE/GEV/Winnow: +1.6 pp at 4x latency on non-reasoning tasks; Pass-2 is perception, GEV itself says thinking "does not help perception").

Practical order of operations: (i) run stock Gemma-4-12B/31B letter readout with images on a held-out-dataset Pass-2 dev set and fit T (hours); (ii) full-FT/LoRA with the Intern-Decision skeleton format (days on 8 GPUs; AJev: 13 h for 65k decisions at 12B on one 96 GB GPU, so 1-5M image decisions is the real cost driver); (iii) add the pointer head for body part/stain/domain and compare against the skeleton symbols; (iv) compare to the SigLIP2/DINOv3 multi-head baseline from the earlier note -- the Space's own SigLIP2 row (6.17) is a zero-shot VQA-style floor and says nothing about supervised closed-set heads.
