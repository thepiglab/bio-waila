# Pass-2 label design: which fields apply to which images, and how to represent each as a label

Generated by `scripts/label_design_analysis.py` from the 3,147 public rows (evaluation-side statistics only), the 393-dataset plan, and `resources/taxonomy.toml`. Machine-readable rules: `label_rules.json`.

## 0. Summary of decisions

1. **Applicability is a conditioning input, not something to predict.** The Pass-2 prompt ends with "Requested metadata fields for this example: ...", so the requested set R is known at inference. In the public split modality, submodality, specimen and domain are annotated for 3147/3147 rows; **stain only ever appears on microscopy** (572/874 microscopy rows = 65.4%, 0 of 2273 others); body part is missing on 309 rows (278 stain-only microscopy rows + 31 clinical-photography-modality rows).
2. Train all six heads on every image where the label exists; use R only to decide which keys to emit. The rules' own example prompt requests only "body part, modality, stain, submodality" (no specimen, domain), so do not assume specimen/domain are always requested in the hidden set even though they are 100% in the public split.
3. **Domain** is a set of 1-3 atoms (82% of rows have one). Parse with: literal_eval, split items on commas, lower/alias/dedupe, unordered set. "obstetrics and gynecology" is one label; "radiology, urology" is two. Verified on all 76 raw strings with zero unmapped atoms.
4. **Body part** is a `|`-joined set only on 379 rows (13.4% of annotated): 280 are hierarchy/synonym pairs (chest|lung), 79 are dataset-level multi-region inventories (esophagus|colon|rectum, colon tissue|lung tissue), 20 are one cell-type list. Train as multi-hot atoms + a 14-way family head; decode general-then-specific.
5. **Modality is the easy root** (submodality determines it for 93% of rows at >=95% purity; H(modality|submodality)=0.10 bits). Recommended decode order: modality -> submodality (masked to legal set) -> body part -> stain (microscopy only) -> specimen -> domain. Domain goes last: it is the least visual and the most annotator-dependent.
6. Deterministic training rules (section 4) resolve 231 non-hard dataset-field cells to hard or family-hard without any model (body-part hard datasets 144 -> 247, plus 62 family-hard) and edit 108 domain sets (rule D1).
7. **Registry domain labels are systematically off from MMBU convention** (radiology on 95-100% of x-ray/CT/MRI datasets vs 10-49% of public rows; oncology on 73% of CT datasets vs 10%). Fix with rule D1 before training.
8. No `unknown` class: the public references never contain it for a requested field, so abstaining can only lose. Keep abstention as an off-by-default threshold.

Practical consequences: the stain head needs no `none` class (a microscopy image with stain requested always has an answer; a not-requested image is simply never scored). ## 2. Multi-label structure

### 2.1 Medical domain

Raw cell format: a python-list string, e.g. `['gastroenterology, radiology', 'surgery', 'radiology']`. Items per list: {1: 2682, 2: 393, 3: 72}; atoms per row after the parsing rule: {1: 2590, 2: 509, 3: 48}.

**Parsing rule** (implemented in `parse_domain` of the analysis script and recorded in `label_rules.json`):

1. `ast.literal_eval` the cell.
2. For each item, split on `\s*,\s*` (item-internal packing: 106 rows in 16 raw strings, e.g. `'urology, radiology'`).
3. Lower-case, collapse whitespace, strip.
4. Alias: `otorhinolaryngology`, `otolaryngology (ent)` -> `otolaryngology`; `infectious diseases` -> `infectious disease`; `gynecology` -> `obstetrics and gynecology`.
5. Dedupe and treat as an **unordered set**: the same pair appears in both orders in raw data (oncology+pathology / pathology+oncology, orthopedics+radiology / radiology+orthopedics, gastroenterology+oncology / oncology+gastroenterology), so order carries no "primary" signal.
6. Never split on ` and `: `obstetrics and gynecology` is the only atom containing it and it is one domain. "radiology, urology" is two labels.

Verification: all 76 distinct raw strings parse; every atom maps to the 23-class vocabulary (0 unmapped, `parse_domain` raises otherwise). Two raw strings contain alias duplicates that collapse after step 4 (`['surgery', 'otolaryngology', 'otorhinolaryngology']` 32 rows; `['gastroenterology, radiology', 'surgery', 'radiology']` 14 rows, where `radiology` appears both packed and standalone). The 3-item lists are 48 rows after dedupe, never more than 3.

Structure: domains behave like **specialty (+ optional discipline)**. Of 557 multi-domain rows, 430 pair a specialty with exactly one discipline atom (radiology, pathology, surgery, biology, cytology), 105 have none (e.g. andrology + urology: 93 rows, all brightfield `sperm cells` images from one dataset) and 22 have two. Radiology is an *add-on*, not the default: it appears on 25% of x-ray/CT/MRI/ultrasound rows (CT 54%, MRI 46%, ultrasound 23%, x-ray 10%). Chest x-ray rows are `pulmonology` alone 93% of the time. Domain is largely **a dataset-level annotator choice**: group-held-out accuracy of predicting domain from (submodality, body part) is 62% vs 92% leave-one-out.

**Recommendation**: multi-label (BCE) over the 23 atoms, cap 3, decoded as: always the argmax atom; add further atoms only if p >= tau (tau ~ 0.5, tune on the validation datasets, not on the public split). Under a semantic judge, one correct atom of two likely earns partial or full credit; a wrong extra atom costs little compared with missing the right one. Do not make "radiology" a default for radiologic modalities (see D1, section 4).

* **Hierarchy/synonym pairs** are written general-to-specific and are *annotation variants of the same thing*. Chest x-ray rows: `chest|lung` 263, `chest` 126, `thorax` 20, `lungs` 10, `heart` 5. A semantic judge will likely accept `chest` for `chest|lung` and vice versa (judge behavior is not documented, so verify on a few examples); the safest output for a chest x-ray is `chest|lung` (exact in 62%, a semantic superset in 30%).
* **Multi-region inventories** (GI endoscopy `esophagus|colon|rectum`, `stomach|colon|esophagus`; LC25000 `colon tissue|lung tissue`) are dataset-level lists; each image shows only one of the listed organs. The best visual answer is the organ actually seen, which is a member of the reference set. Train multi-hot so mass spreads across listed atoms; decode the top atom plus any atom with p >= tau.
* **Cell-type list** (20 rows): five blood-cell names; treat as one class family `blood and lymph`/`white blood cells`.

**Train/evaluate**: pick-one has an exact-match ceiling of 86.6% of annotated rows, but a ceiling of 100% under any-overlap. Because the judge is semantic, use three proxies on the public split: *exact set match*, *Jaccard*, *any-overlap (hit@1 in set)*. Training target = multi-hot over atoms (BCE for hard/multi datasets; `-log sum p(candidates)` for candidates) plus a coarse **family** head (14 anatomical families, table in `label_rules.json`, hard-labelled whenever all registry atoms share a family). Decode: argmax family -> atoms with p >= tau under that family (cap 3), general atom first (`chest|lung`, `eye|retina`).

### 3.3 Predictability between fields

Entropy and majority-vote accuracy of field B given field A on the public rows. H in bits. `acc_loo` is leave-one-out (optimistic: rows of one dataset predict each other); `acc_group` leaves out the whole `metadata_topic` group (224 groups, a dataset proxy) and is the honest number. `base` is the majority-class rate of B. `det` (share of rows whose A-value predicts B at >= 95% purity), `acc_loo` and `base` are in the `predictability` block of `label_rules.json`. Stain is scored with `∅` (not annotated) as a class, so its baseline is high.

|---|---:|---:|---:|---:|---:|---:|
| H(B) | 2.88 | 3.83 | 4.62 | 1.25 | 0.86 | 4.21 |
| modality | - | 1.05 | 2.27 | 0.65 | 0.51 | 1.85 |
| submodality | 0.10 | - | 1.66 | 0.52 | 0.38 | 1.30 |
| body_part | 0.53 | 0.87 | - | 0.43 | 0.31 | 0.65 |
| stain | 2.28 | 3.10 | 3.80 | - | 0.55 | 3.37 |
| specimen | 2.53 | 3.35 | 4.07 | 0.93 | - | 3.75 |

|---|---:|---:|---:|---:|---:|---:|

Findings:

* **submodality -> modality**: H drops 2.88 -> 0.10 bits; 93% of rows are deterministic; group accuracy 94%. The reverse (modality -> submodality) leaves 1.05 bits (75%). Submodality is the finer variable and carries modality inside it.
* **stain** is predictable only through applicability: given modality, `∅` vs stained is exact (0 outside microscopy); given submodality, 76% of rows are deterministic. The stain *value* is not predictable from other fields (given microscopy, H(stain) stays high): it must come from pixels.
* **body part | submodality** removes 3.0 of 4.6 bits in-sample but only 38% group accuracy vs 15% baseline: the family is predictable (strong rules above), the atom is dataset-driven.
* **domain | (submodality, body part)**: H 4.21 -> 0.26 bits in-sample (a dataset fingerprint) but only 62% group accuracy. Domain is the **least transferable** field; predict it last, conditioned on everything else, and do not over-invest in it.
* **specimen** is ~89% `human` and 87% predictable from modality alone (group); the non-human minority sits in fluorescence/EM/light microscopy and ultrasound (`tissue`, `animal`).
* Stain given specimen, domain or body part are all weak for the value; they matter only via applicability.

### 3.4 Decode order

Chain rule makes the joint order-invariant; order matters because of (a) legal-set masking and (b) error propagation. Recommended progressive order:

1. **modality** (11-way; visually the easiest root).
2. **submodality**, logits masked to `legal(modality)` (mean legal-set size is 4.5 (range 1-12) vs 37 unconstrained; only brightfield/WSI/confocal/clinical photography/white-light endoscopy leave modality ambiguous, so decode submodality with a joint (modality, submodality) beam, not a hard commit).
3. **body part**: family first, then atoms (the strong submodality rules fix the family for 8 submodalities).
4. **stain**, only if modality is microscopy (or R contains stain), masked off for never-asked submodalities.
5. **specimen** (89% human prior; non-human only in microscopy/US).
6. **domain**, last, conditioned on modality, submodality and body part.

Domain-first (coarse-to-fine by specialty) is *not* recommended: domain is the noisiest, most annotator-dependent field and predicts modality worse (H(modality|domain)=0.53) than submodality does (0.10). With a plain multi-head classifier the same constraints can be applied post hoc (joint argmax over legal (modality, submodality) pairs, then conditional heads). With a text-contrastive model, score label strings in this order and prune by the compatibility table.

### 4.2 Systematic causes of non-hard labels

* **modality (16 candidate datasets)**: 8 are {digital pathology, light microscopy} (annotation convention, not a real mixture); 8 are registry entries listing two real modalities (optical imaging+x-ray imaging, clinical photography+optical imaging, optical imaging+ultrasound imaging, endoscopy+ultrasound imaging, fluorescence microscopy+light microscopy, light microscopy+optical imaging), i.e. multi-source datasets that need per-image labels.
* **submodality (28 candidate + 2 masked)**: 15 are {colonoscopy|gastroscopy|laparoscopy, white-light endoscopy} (the registry lists the procedure and the generic technique; MMBU files GI endoscopy under `white-light endoscopy` 163 rows vs 5 `colonoscopy`); 4 are {fundus, OCT} true mixtures; 9 other true mixtures; 2 masked (`other`: no MMBU equivalent).
* **body part (222 candidate + 27 masked)**: (i) hierarchical lists inside one family (`eye, retina, optic disc`, `chest, lung`, `brain, head`); (ii) modifiers listed as regions (`blood vessels`, `arteries`) on top of a region; (iii) genuinely multi-region datasets (`abdomen, chest, lymph nodes`); (iv) masked: 11 x more than 4 regions listed (src/bio_waila/data/select.py masks them), 10 x registry says 'not applicable' (simulated/instrument/tracking data), 2 x value outside the vocabulary (leaf epidermis, urine), 4 x registry says 'multiple'. After the ontology, 116 candidate datasets are single-family and 106 span several families.
* **stain (16 candidate, 325 masked)**: 264 masked because the modality is not microscopy (correct: not asked), 61 masked in stained modalities, of which 13 are never-asked submodalities, 13 are cryo-ET/darkfield/synthetic (implied), and 35 have no registry stain at all; 16 candidates are multi-stain datasets.
* **specimen (47 candidate, 13 masked)**: 16+3 are {cell line, human|mouse} (cell line is not a species), 3 {bacteria, e. coli}, human + a second species/phantom, plus 7-species collections; masked ones are `mixed` (plankton, cryo-ET collections) or `unknown`.
* **domain (7 masked)**: registry domains outside MMBU's 23 (`microbiology`, `dentistry`, `vascular medicine`, `general medicine`, `neuroscience`). The other 386 are `multi`.

1. **Domain `radiology` is over-assigned**: 114 of 124 x-ray/CT/MRI/US datasets carry it (6 as the only domain) vs 25% of public rows. As a BCE positive it teaches "every scan is radiology", which would cost the specialty atom (the part the judge can match). Rule D1. Similarly `oncology` on 73% of CT and 53% of MRI datasets (public 10% / 15%), `neurology` 65% vs 18% for MRI, `biology` on 31% of light-microscopy datasets (public 7%), while `pathology` is under-assigned (17% vs 56%) and `surgery` on endoscopy 56% vs 77%. These are share-of-dataset vs share-of-row comparisons, so treat them as direction, not exact rates. Suggest a registry pass: remove `oncology`/`radiology` unless the paper is about tumors/radiology reads.
2. **Body part `cells` is hard for 41 datasets** (10% of the plan): in MMBU, cell-microscopy rows mostly have *no* body part (stain-only rows) and only 23 of 90 fluorescence body-part rows say `cells`. Use low weight, or mask `cells` when a stain is the asked field.
3. **`head` (29 candidate datasets), `optic disc`, `kidney`, `pancreas`, `spine` and about 30 other registry atoms are not MMBU body-part values** (36 of 80 candidate atoms are outside the public vocabulary); the public vocabulary has `brain`, `eye`, `retina`. Fold per B3/B1, and treat out-of-vocabulary atoms as training-only classes mapped to their family at decode time.
4. **Specimen `cell line` (29 datasets) and `phantom` (9) are not MMBU values** (MMBU uses `human`/`Human Cells`, `Kc167 cells`, `Vero cells`, `synthetic`). Map `cell line + species` -> species (SP1) and `phantom` -> `synthetic` only if you want the class.
5. **Modality `digital pathology` is hard for 4 datasets** though only 30/3147 public rows (1%) use it and the same slide images are `light microscopy` elsewhere. Rule M2 for ambiguous cases; consider merging for the modality head and keeping `digital pathology` as an accepted alternate.
6. `cystods` is hard `white-light endoscopy` but its registry also lists `other` (cystoscopy, 450 blue-light frames): small label noise, not worth a rule.
7. **Stain `synthetic` is dropped by `canon_stain`** (it filters any string containing "synthetic"), yet it is the reference value for 38/38 public synthetic-fluorescence rows. Keep it as a class. Likewise `uniform test slide`, `fluorescent beads` appear but are one-offs.
8. `src/bio_waila/data/select.py` masks body part when more than 4 candidates remain (11 datasets). Rule B7 recovers the single-family ones (`galar`, `rhode-island-vce`: all GI organs); whole-body CT sets (`totalsegmentator-v3`, `dap-atlas`, `magic-ct`) span several families and stay masked (or take `whole body` if you want a coarse label).
9. Domains outside MMBU (`dentistry`, `microbiology`, ...) mask 7 datasets; acceptable, but `microbiology` datasets could map to MMBU `biology`/`infectious disease` (3 datasets) if you want the cells.

## 5. Final label schema per field

| field | class list source | prediction type | applicability / training mask | unknown / abstain |
|---|---|---|---|---|
| modality | `taxonomy.toml [modalities].core` (11); `digital pathology` kept but decoded only if p>0.5 | single, softmax | always asked; train on all images | no `unknown` class |
| submodality | public 35 + `fluoroscopy`, `gastroscopy` (37) from `V.SUBMODALITIES`; legal set from section 3.1 | single, softmax, logits masked to legal(modality) via joint (modality, submodality) scoring | always asked; mask the 2 'other' datasets | no `unknown` class |
| body part | atoms: public aliases-merged 66 + registry atoms with >=3 datasets; plus 14-way family head (`label_rules.json`) | multi-label atoms (BCE; partial-label `-log sum p(cand)` for candidates) + single-label family | asked unless modality is clinical photography or stain-only microscopy; mask registry `not applicable`/`multiple`; down-weight generic `cells`/`tissue` | none; decode general-then-specific, cap 3 |
| stain | public canonical stains (h&e, ihc, giemsa, wright-giemsa, papanicolaou, hoechst 33342, gfp, phalloidin, oil red o, uranyl acetate, unstained, ...) + `synthetic` | single, softmax over ~20; optional coarse family head (h&e / ihc / romanowsky / pap / fluorophore / EM heavy metal / unstained / synthetic) | applicable only when modality in {LM, FM, EM, DP}; mask all other images, never-asked submodalities, and microscopy datasets with no registry stain | no `none` class: absence = not requested |
| specimen | `human` + species/cell classes that have >=3 training datasets (mouse, rat, zebrafish, c. elegans, drosophila, bacteria, e. coli, yeast, plant, pig, dog, cat, non-human primate, vero cells, embryo, synthetic, phantom->synthetic) + `other animal` | single, softmax | always asked; mask non-answers (`x-ray images`, `unidentified`, `biological specimen`, `mixed`, `unknown`) | no `unknown` class; default `human` (89%) |
| domain | 23 public atoms (`V.DOMAINS`) | multi-label BCE, max 3; decode top-1 + extras if p>=tau | always possibly asked; mask 7 out-of-vocab datasets; apply D1 (D2 cap of 3 is then moot) | no `unknown` class |

Handling of MMBU non-answers: never include them as classes. In the eval set report scores *with and without* rows whose reference is a non-answer (specimen: 79 rows `x-ray images`/`unidentified`/`biological specimen`, 8 `mixed`; stain: 8 `uniform test slide`, 4 `n/a (not specified)` which `canon_stain` already maps to `unstained`). Predicting the true visual answer costs at most 2.5% of the specimen score and cannot be learned from pixels.

Abstention: references never read `unknown` for a requested field, so `unknown` can only lose points. Provide an off-by-default confidence gate (emit `unknown` only when max p < 0.15) and evaluate it on held-out validation datasets before enabling.

Applicability mask at training time (per image, per field): `mask_f = 0` if the dataset label for f is masked, or if f = stain and the modality is not microscopy or the submodality is never-asked. At inference, emit key f only if f is in the requested set R; all heads still run (cheap), and the stain head is simply not consulted for non-microscopy images.
