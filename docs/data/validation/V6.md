# V6: validation of the 22 force-included MMBU-source datasets (worker w6)

Pilot of 100 images, 2 GB per dataset. Per-dataset records are in `V6.jsonl`. Sample images were looked at on contact sheets of 6 (plus 4 frames from other zips for leukocyte-tem). Where a fix changes the route, the exclude list or the overrides, I verified it by re-running `waila-validate` with a scratch `WAILA_PLAN_DIR` (a copy of `plan/` with the edited `selection.jsonl` / `overrides.csv`); `plan/`, `src/` and the docs were not touched. Bugs B1 to B3 stopped the harness, so those datasets were re-run through a wrapper in my scratch space that patches them in memory. I also compared every label with the MMBU public gold for the same sources (`../mmbu-public/metadata.jsonl`).

Of the 14 fixes, 2 need a `src/` change and have no plan-level workaround (mias: bug B2; mendeley-lbc-hussain-2019: bug B3); bccd is fixed by a route here and by B4 in general.

Findings that matter most:
- **Four datasets would have produced wrong or no images from the registry route:**
  - edd2020: 57% of the media are class-mask TIFFs (`masksPerClass/`), which `is_mask` misses.
  - rat-lung-stereology: only the 1.5 GB *electron microscopy* zip is downloaded, so TEM images get registry-hard "light microscopy / brightfield / toluidine blue" (the metalabel flagged 100/100 modality conflicts).
  - polypgen: the tar-stream sampler hits the 3,216 mask PNGs first, so every sample is blank.
  - bccd: the zip lands in `archives/data/` and is never extracted ("no media found").
- **Two source datasets cannot be read at all today:** mias (.pgm is not an image extension) and mendeley-lbc (Kaggle returns each 2 MB jpg as a zip).
- **mpox-hsam-6class** is a gated HF repo; the same author's Kaggle mirror (same 190 MB) validates, but it has acne/chickenpox/monkeypox/normal classes (91% augmented files), not the six classes in the registry text.
- **The InCell datasets (hcc1143, tnbc)** mix brightfield (TL) channels, labeled fluorescence, with the DAPI/CellMask channels; tnbc also has a `thumbs/` folder of 64 px PNGs (50% of the sample).
- **Label convention vs MMBU gold:** Kather and NCT-CRC H&E patches (103 public rows) are `brightfield microscopy`, empty body part, domain `pathology` in the gold, but the plan says whole slide imaging, colon, oncology+pathology. mpox (5 public rows) is modality `optical imaging` in the gold. sicapv2, mias, octid, bus-bra, hyperkvasir, polypgen, edd2020, lc25000, sbfsem and brain MRI match the gold.
- **Source confirmation by near-duplicates:** mias (about 60% of scanned images), edd2020 (20 of 100), brain MRI (33 of 140), sbfsem, hyperkvasir, mpox, lbc, polypgen, itobos, tnbc all have near-duplicates of mmbu-public, so the force-include guesses are right. bccd has none (0 of 255), so it is probably not the source of its 27 public rows.
- **Low yield:** sbfsem (2 volumes, about 8 images), oro-syzygium (15 images), leukocyte-tem (dropped, 4 near-identical zips), mias (about half of the 322 images overlap the public set).

## Matcher and pipeline bugs

Minimal reproductions are given for each; none was fixed in `src/`.

**B1. `metalabel.load_tables` crashes on a table that has a completely empty column (pandas 3).** The earlier `dropna()` fix leaves an empty string-dtype series, and `.map(...)` on it returns string dtype, so `.mean()` raises. Hit on mias, edd2020, rat-lung (first run) and the hyperkvasir labeled-images zip; whole dataset reports `error: TypeError: Cannot perform reduction 'mean' with string dtype`.
```python
import pandas as pd
s = pd.Series([None, None], dtype=str).dropna().astype(str)
s.map(lambda v: True).mean()      # TypeError: Cannot perform reduction 'mean' with string dtype
```
Fix: `if vals.empty: continue` before the `.mean()` at `metalabel.py:122`.

**B2. `.pgm` (and `.ppm`/`.pnm`) are not in `files.IMAGE_EXT`.** MIAS is 322 PGM images, so prepare reports "no media found". PIL reads PGM.
```python
from bio_waila.data import files; files.kind("all-mias/mdb001.pgm")   # 'other'
```
Fix: add `".pgm", ".ppm", ".pnm"` to `IMAGE_EXT`. With it (in my wrapper) mias gives 100 correct images.

**B3. Kaggle per-file downloads come back zip-wrapped for larger files and `get_file` saves them under the image name.** mendeley-lbc-cervical-cancer: each ~2.2 MB `.jpg` is a ZIP containing the jpg, so prepare reports `reader_error:TiffFileError` for all 140 files. Small files (under about 1 MB, as in sicapv2) come back raw, which is why V5 never saw it.
```bash
uv run waila-download --out /tmp/raw --only mendeley-lbc-hussain-2019 --pilot 8 --max-gb 1
file "/tmp/raw/mendeley-lbc-hussain-2019/files/Squamous cell carcinoma/SCC_3 (2).jpg"   # Zip archive data
```
Fix: in `download.get_file`, after the download, if `"kaggle.com" in e.url`, the name is not a `.zip` and `zipfile.is_zipfile(tmp)`, write the single member's bytes instead.

**B4. `prepare.extract_archives` globs `archives/*` and ignores archives in sub-folders.** HF repos that keep their zips under `data/` (bccd: `archives/data/train.zip`) are never extracted: "no media found", although the download report says done with 140 files.
```python
import tempfile, zipfile, pathlib, io
from PIL import Image
from bio_waila.data import prepare as pp
d = pathlib.Path(tempfile.mkdtemp()); (d/"archives"/"data").mkdir(parents=True)
b = io.BytesIO(); Image.new("RGB", (8, 8)).save(b, "PNG")
zipfile.ZipFile(d/"archives"/"data"/"train.zip", "w").writestr("a.png", b.getvalue())
pp.extract_archives(d); len(pp.find_media(d))     # 0, expected 1
```
Fix: iterate `(root/"archives").rglob("*")` over files and use the relative path (with `/` replaced) for the extraction folder and `.ok` marker.

**B5. `files.is_mask` judges only the last two path components, so a mask folder one level above the class folder is missed.** edd2020: `EDD2020/masksPerClass/BE/EDD2020_B0003_BE.tif` is not a mask (502 of 888 media are such files). Also `.../validation/targets/x.png` (PolypGen HF tar; `targets` is not in `_MASK` outside `training_target`/`target_masks`).
```python
from bio_waila.data import files
files.is_mask("EDD2020/masksPerClass/BE/EDD2020_B0003_BE.tif")   # False
```
Fix: also test the third-from-last component (or all components, with the dataset root excluded), and add `targets?` and `thumbs?`/`thumbnails?` to `_MASK` or to the junk filter.

**B6. The archive sampler assumes the first archive satisfies the whole quota ("got += want") and, for tar streams, keeps the first N media members in tar order.** Consequences: rat-lung (only the 1.5 GB EM zip of two zips is fetched), leukocyte-tem (1 of 5 zips, 45 images), polypgen HF tar (first 140 members are masks). Repro: `uv run waila-download --out /tmp/raw --only rat-lung-stereology-lm-tem-zenodo-3738928 --pilot 100` then list `/tmp/raw/rat-lung-.../archives` (only `Electron microscopy.zip`). Fix: when a record has several archives, fetch more than one (spread the quota over archives, smallest first) and prefer archives whose name or listing does not contain a mask-like word; for tar streams, skip `is_mask` members while streaming (they are counted today because `targets` is not recognised, see B5).

**B7. HF streaming sampler: class diversity and structure.** (a) On parquet files sorted by label (Kather, NCT-CRC), `shuffle(buffer_size=2000)` only mixes the first 2,000 rows, so the pilot sample has 4 of the 8 classes (kather) and the full-run sample would too if `want` is below the repo size. (b) HF zip-only repos (HyperKvasir) are read as an image folder without folder names (`hf:label` is absent), losing the class/anatomy information that the zip route keeps. Not blocking; visible in V6 reports of kather-crc-texture-2016 and hyperkvasir.

**B8. `plan_images` for volume-only repos is not what prepare delivers.** sbfsem-vero-sars-cov-2-mitochondria lists 281 effective images but the repo is 2 volumes, and prepare takes 4 slices per volume (6 images were prepared). Same shape: oro-syzygium (plan 1000, 15 images). Consider capping `plan_images` by the listed file count x per-file yield when the route lists few files.
