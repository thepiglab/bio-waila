## Remaining pipeline bugs (with minimal reproductions)
1. P-INFORMATIVE, real images discarded. `prepare.informative()` uses luma (std > 6 and >5% of pixels > 10). Dim single-colour fluorescence fails it. Repro: `uv run waila-validate --only fluorescent-neuronal-cells-v2 --redo` gives `blank_or_tiny: 82` of 140; or in Python, a 384x512 RGB image with only the red channel (background 8-14, 15% of pixels 28-64) gives luma std 3.9, `informative()` False, while max-over-channels std/coverage pass. Suggest computing the test on `np.asarray(im).max(2)` (or per-channel).
2. P-BUDGET, `--max-gb` not enforced for some strategies: lask (zip-range+zip-range) downloaded 3.37 GB, spinedl-mouse-spinal-cord (whole+zip-range) 2.13 GB, mll23-peripheral-blood and pcle-pto 2.07-2.1 GB (single whole archive, unavoidable). Repro: `--only lask` (raw dir reached 3.3 GB before this was noticed; the lask run predates the budget-enforcing sample_zip_remote now in src, re-check).
3. P-ARCH, archive spread: bicervi-2026 (9 listed class archives, only NILM fetched) and mll23-peripheral-blood (18 class zips, only myeloblast fetched, 100% one class). Repro: `--only bicervi-2026` and check `listed_files` vs `n_media`/folders.
4. P-HFSAMPLE, single-class HF sample: kather-crc-texture-2016 returns 140 rows that are all ADIPOSE (parquet sorted by class; `shuffle(buffer_size=100)` does not mix). Probably fixed by the new evenly-spaced row-group sampling, re-run to confirm.
5. nsclc-radiogenomics: hf-files fallback picks 35 files from one patient (R01-027); `list_repo_tree` returns 752 files for 146 patients, so the sampler is not spreading over patients (many are extension-less DICOMs). Also pulls DERIVED/REFORMATTED coronal series; DICOM ImageType is not usable in exclude_paths.
6. P-EXIF: prepare never applies EXIF orientation (`Image.open` without `ImageOps.exif_transpose`). diabetic-foot-early-markers-kem S0 comes out rotated 90 degrees. Affects every phone/camera photo dataset.
7. P-VIDEO-GLITCH: polyp-size still yields a colour-noise frame (decode glitch after seeking); `informative()` passes it. Repro: `--only polyp-size`, sample S2 in the report.
8. rarfile + bsdtar fallback: colorectal-polyps-gaze extracts a single bogus entry (`Type 1/()`), prepare reports `reader_error:TiffFileError` instead of "unrar missing". `extracted/<name>.err` exists but is not surfaced in the report.
9. Source-image orientation: segthy (flipped) and tom500-thyroid-eye-orbital-mri (rotated 90) are baked into HF preview PNGs; only a per-dataset flip/rotate option could fix them.
10. Cosmetic: spurious `bids:ce`/`bids:suffix` columns from hex or numeric file names (bm-broncholc, nachos, periorbital); vestibular-schwannoma-seg review lists `hf:preview_slice` numbers as submodality; mito-live-cell-segmentation logs 99 specimen conflicts because `path:d2=M1_U2OS` matches class "cell line" vs registry "human".
11. In-dataset dedup misses near-identical frames (cystoscopy-nerf-frames, ht1080-3d-collagen-phase-tracking, lask, polyp-size) and triple-folder duplicates (rvo-me-oct: same 3,012 B-scans in three task folders; nachos: three split folders).
12. Grey vs colour is not usable as evidence: retinal-avm-case-fa-ghent submodality stays an FA/fundus candidate pair although 2 of 8 samples are colour fundus.
