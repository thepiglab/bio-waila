# N4: validation of 13 datasets (worker n4)

Ids from `data/cache/assign/n4.txt`, run as three parallel processes (`n4a`: 5 ids, `n4b`: 4, `n4c`: 4) with `uv run waila-validate --only <list> --worker n4x --pilot 100 --max-gb 2 --redo`, no `--keep-raw`. Sample sheets (8 images with their labels) were viewed for every dataset that produced images; for skin-lesion-yolo-det-10class (30 images), mihic (extra 16 'Other' tiles) and cystods (nearest public images) extra sheets were viewed. Proposed fixes for wbc-hr-bodzas-2023 and drends were re-run against a copy of `plan/` (`WAILA_PLAN_DIR`) with a scratch `--root`, which was deleted afterwards. All proposed values are in `plan/label_space.json`. `src/`, `plan/` and other agents' files were not touched.

## Pipeline bugs

1. **`near_mmbu_public` dHash is too coarse and drops most circular-field images.** `prepare.dhash` is a 9x8 gradient hash (64 bits) and `NEAR_DUP_BITS = 4`. Cystoscopy frames (dark border plus bright circle) collide with unrelated public images. Reproduction: `uv run waila-validate --only cystods --worker x --pilot 100 --redo` gives `prepare: media_files 280, kept 35, near_mmbu_public 245` although `mmbu_public_rows` is 0 and `mmbu-public` has no cystoscopy rows. Kept cystods images sit at distance 5 to 8 from public hashes, and the nearest public images of kept cystoscopy frames are fundus photos and a mammogram (viewed side by side). Other datasets in this batch show the same effect (spacr-cross-channel-toxoplasma: 28 of 140 dropped; drends: 18). Suggest a larger hash (16x16, 256 bits) or a second check (e.g. colour histogram or a 32x32 thumbnail correlation) before counting two images as duplicates, and report the near-dup rate per dataset so >30% drops are flagged.
2. **RAR archives fail silently.** `prepare.extract_archives` imports `rarfile`, which is not installed in the uv environment and has no `unrar`/`unar` binary on PATH. The exception is written to `extracted/<name>.err` and the dataset ends as `no images prepared` / `no media found`. Reproduction: `uv run waila-validate --only lunghist700 --worker x --pilot 100 --redo` (figshare 25459174, one 670 MB RAR). macOS `/usr/bin/bsdtar` (libarchive 3.7.4) can read RAR, so a `subprocess.run(['bsdtar','-xf',a,'-C',dest])` fallback would work without installing anything (not tested on this archive). Also, the validate status should say `blocked: rar` rather than `no images prepared`.
3. **Unmapped path values are neither labelled nor listed for review.** In drends, `path:d1` values `Vid04_Intestine_Med` and `Vid05_Intestine_High` get no body_part (the generic word 'intestine' is not auto-mapped, and only `Seq03/04/05` have overrides), but `review_values` is `[]`. Reproduction: `uv run waila-validate --only drends --worker x --pilot 100 --redo`, then read `review_values` and the body_part rows of the Vid04 samples. Values that fail to map in a column that is otherwise trusted (5 of 7 values mapped) should appear in `review.csv`.
4. **Minor: hard overrides are intersected with registry candidates.** With a registry `candidates` mode for a field, `resolve` drops metadata classes that are not in the candidate list, so a hand override such as `Lymphocyte -> lymphocytes` is lost silently. Reproduction: set wbc-hr-bodzas-2023 body_part to candidates [blood, white blood cells] in a plan copy and add the nine `path:d2` override rows; only the 33% of images whose override value is in the list become hard. Document this or let overrides replace the candidate set.
5. **Minor: `blank_or_tiny` drops 30% of pale ZN sputum smears** (152 of 512 in ai-tb-zn-uganda-2026). Both classes are still present in the 100 kept images, so there is no label bias seen, but the threshold could be checked against low-contrast brightfield fields.
