## Matcher / pipeline bugs (with reproductions)

1. validate.py:88 `pd.read_csv(work/metalabel/review.csv)` raises EmptyDataError when the dataset has no values to review (metalabel `map` writes a 0/1-byte review.csv). Repro: `uv run waila-validate --only wbcatt-plus-2026 --worker x` -> 'error: EmptyDataError: No columns to parse from file'; raw is deleted, so the whole download is wasted. Hit wbcatt-plus-2026, pbc-acevedo-2020, lidc-idri. Fix: write the header row in metalabel.cmd_map even when empty, and/or catch EmptyDataError in validate.py.

2. metalabel.load_tables (metalabel.py:116-117) crashes under pandas 3.0.6 because `Series.astype(str)` now keeps NaN as float NaN, so `Path(v)` raises 'TypeError: argument should be a str or an os.PathLike object ..., not float'. Repro: any CSV with an empty cell next to media-key columns, e.g. glioma-warsaw-multiparametric-2026 (files/*.csv). Fix: `df[c].fillna('').astype(str)`; same pattern (`.astype(str)` then string ops) should be audited across metalabel.py/prepare.py.

3. openorganelle: dl hf strategy loads whole parquet shards; shards of eminorhan/openorganelle-2d are ~6.3 GB each (1000 shards, 6.35 TB) -> 'ArrowInvalid: offset overflow while concatenating arrays' and blows the budget. The HF route needs a row-group/HTTP-range or datasets-server /rows sampling path for datasets whose shards exceed --max-gb.

4. metalabel.load_tables/key_candidates: a low-cardinality column can be chosen as the join key because key_candidates() adds the parent folder name. Repro: tissue-fold-teaching-slides (files/metadata.csv columns image_filename, class in {clean,tissue_fold}, organ; images under images/<Organ>/<class>/x.jpg): `class` scores 1.0 (parent folder name == class) so after drop_duplicates('class') the table has 2 rows and every image inherits organ=Brain (100% wrong body_part for Kidney/Liver/Testis/Small_Intestine images). Fix: require the join column to be near-unique (n_distinct >= 0.5*n_rows) and prefer file-name matches over parent-folder matches; never join on a column that has fewer distinct values than media files unless it is a patient id with >=1 file per value and the table has one row per key.

5. match_value("t1", "hf:modality", cls) returns only {'modality': ('magnetic resonance imaging', True)} (same for t2, pd, qt1); match_value("flair", "hf:modality", cls) returns both modality and submodality 'structural mri'. Expected: t1/t2/pd/t1w/t2w also give submodality 'structural mri' (CODES['submodality'] is only consulted when the column name matches the submodality regex). Repro dataset: synthstrip-dataset (hf:modality = t1, t2, pd, flair, mra, epi, qt1); with overrides the submodality resolves for 69% of rows.

6. PATH_CODES: a folder named T1/T2 is always read as MRI weighting. match_value('T1', 'path:d4', cls) -> {'submodality': ('structural mri', True)}; in mslesseg-2024 (P24/T1/P24_T1_T1.nii.gz) d4 is the visit number (T1..T4). Also review lists T3/T4 as unmapped. Harmless for MRI-only datasets but would mislabel e.g. longitudinal CT/US studies. Require the sibling values to look like sequences (not T1..T9 sequentially) or ignore when file stem repeats the value (P24_T1_T1).

7. download.fetch_hf: errors raised while iterating the streaming dataset are not caught, so the hf-files fallback is skipped. Repro: `uv run python -c "import datasets; d=datasets.load_dataset('pytc/MitoEM', streaming=True); next(iter(d['train']))"` -> ValueError: Invalid string class label MitoEM@<sha>. Fix: wrap the `for i, ex in enumerate(it)` loop in try/except and fall back to the file listing.

8. download.fetch_hf (same bug as mitoem): iteration errors are not caught. Repro: `uv run python -c "import datasets; d=datasets.load_dataset('MartialTerran/Cervical_Spine_X-ray_Atlas_CSXA_V3.0', streaming=True); next(iter(d['train']))"` -> ArrowInvalid: JSON parse error (repo only has zip/xlsx/py files). Detect `features is None` / Unknown features after load_dataset(streaming) as a signal to use the file route.

9. COLUMN_MIN (0.6) vs 'Other' bucket: a column whose values are all body parts except a catch-all 'Other' bucket is rejected. Repro: fetal-planes-db csv Plane: Other 34%, Fetal brain 25%, Fetal thorax 14%, Maternal cervix 13%, Fetal femur 8%, Fetal abdomen 6% -> mapped share 0.576 < 0.6, column untrusted, body_part left as candidates. Suggest: ignore catch-all values (other/unknown/misc/background/none/normal) in the denominator, and treat 'femur/tibia/humerus/radius' as limb classes (lower/upper limbs) when no better class exists.

10. download.sample_zip_remote on figshare: presigned S3 URL has X-Amz-Expires=10, so later range requests return 403 (RemoteIOError). Repro: `uv run waila-validate --only mcoa-corneal-opacity --worker x` -> 'RemoteIOError: 403 Client Error: Forbidden for url: https://s3-eu-west-1.amazonaws.com/pstorage-npg-.../MCOA_Dataset.zip?X-Amz-...&X-Amz-Expires=10'. Fix: re-request https://ndownloader.figshare.com/files/<id> (302) before each range read, or on 403.

11. download.fetch_hf iteration error (3rd case). Repro: `uv run python -c "import datasets; d=datasets.load_dataset('makhresearch/skin-lesion-segmentation-classification', streaming=True); [x for _,x in zip(range(300), d['train'])]"` -> UnidentifiedImageError (YOLO .txt members in the imagefolder). Same fix as mitoem/csxa: catch exceptions around the iteration and fall back to the file route.

12. prepare.py (reader_error:RuntimeError, mammo-mx): pydicom 3.0.2 + Pillow only; uv env has no pylibjpeg/gdcm/imagecodecs, so compressed-transfer-syntax DICOMs cannot be decoded. Repro: `uv run waila-validate --only mammo-mx --worker x` -> status 'no images prepared', prepare: {'state':'empty','reader_error:RuntimeError':140}. Cause not confirmed on the raw files (deleted); verify with `ds.file_meta.TransferSyntaxUID` and `ds.pixel_array`. Affects every compressed-DICOM dataset (likely also other mammography/CT sets).

13. files.is_mask/mask filter misses unlabeled mask duplicates: her2-tqi-valparaiso has 'HER2 COHORTE 2 IMAGES/Nueva Carpeta/HER2007.jpg' (binary mask) next to 'HER2007.jpg' (RGB IHC). Repro: sample 8 images of her2-tqi-valparaiso, 3 are black/white masks. Suggest a content-based mask check in prepare (>=95% pixels in {0,255}, <=2 grey levels, single channel) and/or a same-stem-duplicate-across-sibling-folders heuristic.

14. mask filter does not recognise suffix codes: fovea-intraoperative-fundus 'FOVEA014_p_ve_2.png' (binary vessel mask) and 'FOVEA019_i_raw_1.png' (pseudo-colour label map). Repro: 6 of 8 sampled images are not fundus photographs. Combined with the content check suggested for her2-tqi-valparaiso (near-binary / <=4 colours / palette images) these would be rejected.

15. match_value('human', 'path:d2', cls) returns {} (weak specimen keyword, no ctx), so a folder column of species names maps only the strong ones. Repro: oocytor-oocyte-segmentation path:d2 values mouse/human/sea_urchin -> mouse 52% < COLUMN_MIN so specimen is never used. Suggest: for path columns, accept an exact folder name equal to a specimen class ('human','mouse','rat','pig','dog'...) as strong (like PATH_CODES), since a folder named exactly 'human' is unambiguous.

16. download.resolve_doi: DOIs 10.25532/OPARA-* resolve to https://opara.zih.tu-dresden.de/items/<uuid> (DSpace 7); state 'manual'. Repro: `uv run waila-validate --only appendix300,d4d-dresden-4d-reconstruction`. A DSpace 7 lister (REST API, no login for public items) would unblock both (and any other OPARA datasets).

17. metalabel.path_columns ignores the file-name stem (only folders and BIDS key-value entities are columns), so words in file names never reach the matcher. Repro: cusi-mouse-4d-brain-hemodynamics files/Awake_Color_Doppler.nii and files/Awake_Power_Doppler.nii: submodality candidates [3d ultrasound, color doppler] stay unresolved although text_hits('Awake_Color_Doppler') -> color doppler. Same for FOVEA014_p_ve_2.png, HER2007.jpg, T1w-less MRI names etc. Suggest adding a `path:stem` column (digits/ids stripped, low-cardinality only) and running match_value over it.

18. metalabel.load_tables: every small CSV is tried as a join table, so datasets with one point-annotation CSV per image (cellfmcount: 2,506 files x 2 columns X,Y) produce thousands of useless table columns and slow profiling. Repro: cellfmcount profile. Suggest skipping tables whose key column matches <=1 media file (score on number of distinct matched keys, not share) and columns named X/Y/x/y/width/height.

19. mask filter does not catch '*_CELLMASK.png' (also *_MASK, *CELLMASK). Repro: bbbc031: 8/8 sampled images are CELLMASK renders.

20. prepare.py TIFF reader: tifffile.TiffFileError on the aattct-ids patient_001 stack (1.5 GB). Repro: `uv run waila-validate --only aattct-ids` -> 'no images prepared', reader_error:TiffFileError: 1. Probably needs `imagecodecs` (compressed TIFF) - not in the uv env.

21. download --max-gb not enforced (before the coordinator fix): lask pulled 3.4 GB (two zip-range strategies), msd-task03-liver 1.95 GB, verse-style hf-files fallback used a 50 GiB budget; several figshare 'whole' downloads sat at 1.5-1.9 GB for 140 images (bdcxr, cisd-urine-cytology, bcdd-sust-dengue, clinical-bacteria-gram). Consider a pre-flight: when a record is one big zip use range sampling, never whole-file above --max-gb.

22. Disk-full ENOSPC: at 12:00 the volume had ~17 GB free while the cache cap is 20 GB, so a worker hit 'OSError: [Errno 28] No space left on device' (ispy2 first attempt, rescale4dl). The cache guard should also check free disk space (it does now: 'disk free ... (min 8 GB)').

23. download.sample_zip_remote: NotImplementedError 'That compression method is not supported' for TanCY1/I-SPY_2_..._DCE-MRI_Dataset ISPY2_T0_T3_DCE_npz.zip. Repro: `uv run waila-validate --only ispy2 --worker x`. Catch NotImplementedError per member and fall back to the tar.gz sibling (sample_tar_stream) or install `zipfile-deflate64`.
