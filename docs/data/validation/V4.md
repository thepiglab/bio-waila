# V4: validation of the w4 list (90 datasets)

Worker: w4 (plus w4b..w4h helper work dirs for parallel batches). Harness: `uv run waila-validate --only ... --pilot 100 --max-gb 2`, 3-5 ids per batch, cache checked before each batch (waiting at >=17-18 GB; the shared cache peaked at 18.9 GB once, when another worker's ispy2 alone held 12 GB). For each dataset I read the report and looked at an 8-image contact sheet of the prepared sample. Where the early pipeline bugs hit (pandas-3 NaN, empty review.csv, no-profile OSError) I re-ran with a local wrapper (scratchpad only, src untouched) or, after the coordinator's fixes, with plain `--redo`.

## Matcher / pipeline bugs (with minimal reproductions)
Already fixed by the coordinator during my run: (a) pandas 3 NaN in `metalabel.load_tables` (`pd.read_csv(..., dtype=str)` then `Series.astype(str)` keeps NaN, `Path(nan)` raises TypeError: sustech-sysu, vetxray, mitoem-2); (b) empty `review.csv` crashed `validate.py` (`pd.read_csv` EmptyDataError: first cellmap-challenge-2025 run); (c) `cmd_map` wrote into a missing `work/<w>/metalabel` dir when no profile was produced (mitoem-2); (d) hf-files fallback ignored `--max-gb` (totalsegmentator-v2 started a 22.6 GB Images.zip).

Still open:
1. JPEG-Lossless DICOM cannot be decoded: no gdcm/pylibjpeg. Repro: `uv run waila-validate --only head-cta-intracranial-aneurysm-dicom-2025` gives prepare `reader_error:RuntimeError: 35`; `pydicom.dcmread(f).pixel_array` on TransferSyntax 1.2.840.10008.1.2.4.70 says "all plugins are missing dependencies: gdcm, pylibjpeg-libjpeg". Fix: add pylibjpeg, pylibjpeg-libjpeg, pylibjpeg-openjpeg to pyproject (or SimpleITK fallback).
2. HF streaming `ArrowInvalid: offset overflow while concatenating arrays` for datasets with multi-MB images (shuffle buffer 2000): `uv run waila-validate --only isic-2017,lacuna-malaria-2024 --redo` fails both, also after the coordinator's budget fix. Fix: size the shuffle buffer by bytes (e.g. 200 MB / image size) or skip shuffling and read row groups.
3. HF repo with mixed-schema CSVs (`harvardairobotics/FairFedMed`): `load_dataset` raises `ArrowInvalid: Schema at index 1 was different` and the files fallback is not entered (only `load_dataset()` is wrapped, not iteration). Fix: wrap iteration too.
4. Streamed HF datasets lose ClassLabel names: `hf_rows.jsonl` has ints (feltrin-brain-tumor-mri-44c `hf:label` = 0..13). Any class-name based mapping of ClassLabel columns is impossible there. Fix: `features[col].int2str`.
5. `match_value("MemBrain_seg_training_data","path:d1",cls)` returns `{'body_part': ('brain', True)}`; expected `{}` ("MemBrain" must not match brain; needs a word boundary). Conflict logged on 100% of membrain-seg-training-data rows.
6. `match_value("AP","dicom:ViewPosition",cls)` and "PA" return `{'submodality': ('chest x-ray', True)}` for any anatomy; a knee AP radiograph would be labelled chest x-ray. Gate on BodyPartExamined=CHEST.
7. Matcher gaps: `match_value("PC microscopy","path:d2",cls)` and `"PC"` return `{}` (expected phase contrast microscopy); `"cats"`, `"pigs"`, `"cows"`, `"feline"` return `{}` for specimen while `"dogs"`, `"mice"`, `"rats"`, `"canine"`, `"murine"` match; `"dogs"` and `"canine"` are only weak (False) in a path column so they cannot resolve a candidate set (leishmania-canine-node-smears stays {dog, leishmania}). `"thorax"` does not alias to chest.
8. DICOM tables: `BodyPartExamined` `UP_EXM`/`LOW_EXM` (vendor codes) are unmapped (vetxray: `match_value("UP_EXM","dicom:BodyPartExamined",cls)` -> {}, should be upper limbs / lower limbs); species tags (PatientSpeciesDescription 0010,2201, BreedDescription 0010,2202) are not in the header tag list, so veterinary DICOM stays cat/dog ambiguous.
9. `FIELD_COLUMNS` regexes are too loose and the review list ignores `SKIP_COLUMN`: "protocol" matches `DR_grade(Scottish_DR_grading_protocol)` (sustech-sysu), "acqui" matches `acquired_pe_lines`/`single_acquisition_repetition` (m4raw-abdomen), "sequence" matches video sequence ids `004-004` (real-colon), file-path column `location` (mm-mcd-myeloma-2026), tumour-location codes 1/2/3 (pancreas-pda-segmentations-mayo). Only review noise, but it buries real review items.
10. Registry candidate sets silently reject better evidence: viralskin-4 (`Mouth` -> oral cavity is outside {face, foot, hand, skin}, so the mouth image keeps foot/hand as candidates), recist-ct-hcuch (`thorax` outside {abdomen, chest, lymph nodes}, 87% of images stay candidates). Suggest: when strong metadata evidence falls outside the candidate set, log a conflict row and (optionally) union it, instead of dropping it.
11. COLUMN_MIN=0.6 discards informative minority folders (oriented-instrument-hysterectomy `dataset_phantom` = 25% of rows, mcr-sl `clinical` weak, polimi-stereo-rarp phase folders, qpi-labelfree DIC/HMC/PC/QPI). The coordinator's note says overrides are now always trusted; the overrides above rely on that.
12. Filename tokens are not exposed as columns: `Channel1/Channel2` (bbbc013 -> gfp/draq5), `chlamy_/spinach_` (membrain-seg -> chlamydomonas/plant), `--Stained--/--NonStained--` (arabidopsis -> unstained), BIDS-like `bp-chest_vp-ap` (cov-caldas), hyphen-separated `-t1n/-t2w` (brats-africa). Proposal: a `stem:tokenN` column family.
13. Mask/overlay filter gaps: `binary.png` (cardiag), `*_GT/TRA/man_track*.tif` (tracking-one-in-a-million), `*--img.png` RRQuant outputs (arabidopsis), `assets/representative_images.png` figure (m4raw-abdomen), `motion_debug.png` plots (open-h-embodiment), `visualization/` (hepg2-dic), overlays baked into the pixels of the HF render (spinal-multiple-myeloma-seg: cannot be filtered by name).
14. Arrays: `.npy` embedding matrices are rendered as images (murine-cell-lines-phase-xiong `masked_model_penultimate_embeddings.npy`); `(N,H,W,3)` RGB stacks are treated as volumes and yield 4 grey slices from 1.8 GB (intel-mobileodt-refined-766).
15. Slice axis = `argmin(shape[:3])` picks sagittal/coronal planes for many CT volumes (curvas-pdacvi 4/8 samples sagittal, totalsegmentator-v2, rcc-aid); the middle 30-70% slice rule gives lung/pelvis slices for abdomen datasets (pancreas-pda-segmentations-mayo, recist, curvas); the CT display window is wide, soft tissue is washed out (msd-task08, rcc-aid, pancreas). Use the NIfTI affine to find the axial axis and a soft-tissue window for abdomen.
16. Budget is per-file: zip-range members that are 70-1800 MB blow `--max-gb 2`: curvas-pdacvi 4.57 GB, membrain-seg-training-data 2.47 GB, medsegmnist-derm2d 2.14 GB, recist 2.1 GB, pcle-pto 2.1 GB, drends was at 3.6 GB (two 1.8 GB mp4 members) after an hour when I killed it. Skip members larger than the remaining budget.
17. Archive sampler: when one zip per class exists it takes one archive only (mll23-peripheral-blood: all 100 images are myeloblasts from a single 2.07 GB zip of 18); `.rar` is unsupported (cmha, egid-gastritis, exodeepfinder: 14-40 GB of rar, nothing sampled); tvus-ovarian only sampled `images_normal`.
18. `prepare` rejected every slice of prostate-ppat-healthy-longitudinal-2026 (`state: empty`, blank_or_tiny=670, near_public=50) although they are real T2 prostate volumes; likely `informative()` or `to_uint8` scaling. Repro: `uv run waila-validate --only prostate-ppat-healthy-longitudinal-2026`.
19. `reader_error:TiffFileError` on `.jpg` files (siop-periodontal 4, pressure-injury-iran 7): `read_image` falls back to `tifffile` on any PIL exception and reports the tifffile error, hiding the real one. All 195 pressure-injury files open fine with PIL in isolation, so the cause is unknown.
20. Metadata tables explode columns: per-patient json/tsv are loaded as separate tables (cardiag 386 columns, code-oral-mucosa 84, cov-caldas 69, murine-cell-lines 1053); headerless csv uses the first row as header (ralo-score-dataset columns "0".."12").
21. Environment: the local disk filled up (3.7 GB free) around 12:15; five of my runs died with `OSError: [Errno 28]` (medsegmnist-derm2d, s3d-spine-detection-2p, membrain-seg-training-data, prostate-ppat, totalsegmentator-v2). I stopped all drivers, cleaned my raw leftovers and resumed when 12+ GB were free.
