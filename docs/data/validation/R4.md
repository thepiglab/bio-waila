## Content-based mask filter

`prepare`'s stats contain no `looks_like_mask` key for any of the 21 datasets, i.e. the filter dropped 0 images, so it removed no real image. This includes the risky cases: shoulder-implant radiographs with large black borders, high-contrast DIC frames in mcellseg, 128 px grey sperm crops in shseg/mhsma, dark fundus frames in drimdb (9 of 100 kept images have mean grey below 40 and 2 below 25; they pass `informative()` and are real "Bad quality" fundus photos). No mask images turned up in any sample either, so the folder/name filters and `exclude_paths` do the work and the content check had nothing to catch here.

## Remaining bugs with reproductions

**1. `prepare.read_array` yields only `SLICES_PER_VOLUME` (4) images from an `(N, H, W)` stack of independent images, so mhsma gives about 10 images instead of 1,540.** The three `x_128_{train,valid,test}.npy` files hold 1000 / 240 / 300 single-sperm crops each; 12 items are sampled and 2 are dropped as blank. (Before the fix these were the garbage strips; the images are now correct.)
```python
import numpy as np, tempfile, pathlib
from bio_waila.data import prepare as pp
p = pathlib.Path(tempfile.mkdtemp()) / "x_128_train.npy"
np.save(p, (np.random.rand(1000, 128, 128) * 255).astype(np.uint8))
len(list(pp.read_array(p)))      # 4, expected about target / n_stack_files
```
Fix: for `(N, H, W)` or `(N, H, W, C)` stacks of crops (`H, W` small, `N` large) sample `min(N, ceil(target / n_stack_files))` items per file instead of 4. Until then mhsma contributes about 10 training images; do not count its `plan_images` 1,540. The download also reports state `partial` (20 media, 15 removed by `exclude_paths`).

**2. `download.list_kaggle(max_files=50_000)` still stops at 50,001 files, so large per-file Kaggle datasets are sampled from the first 50k paths only.** nih-chestxray14: `path:d1` of the sample shows only `images_001` to `images_006` (23 to 24 files each); `images_007` to `images_012` (about half of the 112,120 radiographs) are never sampled. Low impact for the labels (all registry-hard) but a patient-ordered bias. vip20k shrank from 50,001 to 33,322 listed files because `/Merge/` is now excluded at listing time, so it is no longer truncated.
```bash
uv run waila-validate --only nih-chestxray14 --worker r4 --pilot 100 --max-gb 2 --redo
# report: download.listed_files == 50001, metadata path:d1 only images_001..006
```

**3. The new one-hot indicator rule trusts a continuous measurement column.** uci-digital-colposcopy-quality: `green.csv`, `hinselmann.csv` and `schiller.csv` column `cervix_area` (a quality ratio, value `"1.0"` for 18 rows each) is listed in `trusted_columns` as `body_part: cervix` with source `indicator`. It agrees with the registry here (so harmless), but on another dataset a numeric column named after a body part would be read as a flag.
```bash
uv run waila-validate --only uci-digital-colposcopy-quality --worker r4 --pilot 100 --max-gb 2 --redo
python3 -c "import json;print(json.load(open('data/cache/reports/uci-digital-colposcopy-quality.json'))['trusted_columns'].keys())"
```
Fix: only accept the indicator rule for columns whose distinct values are exactly two (0/1, true/false, yes/no), not a float with many distinct values.
