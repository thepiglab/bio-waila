## Matcher / pipeline bugs (with minimal reproductions)

- **P2** validate.py read_csv on empty review.csv (FIXED by coordinator)
  - Repro: run waila-validate on any dataset with no review values (e.g. scin, taix-ray): pd.read_csv(work/metalabel/review.csv) raises EmptyDataError because the file is 0 bytes.
- **P3** download.fetch_hf fallback ignores --max-gb (PARTLY FIXED: verse-2019 re-run now pulls 2.02 GB (was 4.28 GB), but budget is still exceeded on zenodo zip-range / multi-zip paths)
  - Repro: uv run waila-validate --only verse-2019 --max-gb 2 downloaded 4.28 GB; nih-chestxray14 downloaded a 4.19 GB images_011.zip whole (fetch_entries(..., 50 * 2**30, ...) in fetch_hf). Also magic-ct (zenodo zip-range) grew to 3.5 GB+ for one dataset with the old code. Still over budget after the fix: surgpose (zenodo 15278516, 34 zips) pulled 5.25 GB with --max-gb 2 ('whole+zip-range x5'); magic-ct (zenodo zip-range of 100 MB .nrrd volumes) pulled 3.16 GB.
- **P4** HF ClassLabel integers are written to hf_rows.jsonl instead of class names
  - Repro: nf-whoi/whoi-plankton: datasets.load_dataset(..., streaming=True)['train'].features['label'] is ClassLabel(names=['Amphidinium_sp',...]); the report column hf:label shows ints 86, 47, 7 (top values) so the taxon names never reach match_value. Expected: fetch_hf should write features[k].int2str(v) for ClassLabel columns (this is exactly where organ/diagnosis names live in many HF datasets).
- **P5** field_of_column maps unrelated column names to body_part
  - Repro: field_of_column('hf:frac_in_tissue') == 'body_part' and field_of_column('hf:in_participants_tsv') == 'body_part' (expected None). Produced spurious review rows (tompei-cmmd frac_in_tissue=1.0, soop-stroke in_participants_tsv=True). Substring match on 'tissue' / 'part' should be word-boundary on the column's tokens.
- **P6** HfApi.dataset_info(...).siblings is truncated for big repos; fetch_hf fallback samples one patient
  - Repro: MedOtter/NSCLC-Radiogenomics: len(dataset_info(files_metadata=True).siblings)==752 but list(list_repo_tree(repo_type='dataset', recursive=True)) has 2066 entries over 144 patient dirs; the fallback sampled 35 slices from the single patient R01-027 (all path:d1 values identical). Use list_repo_tree(recursive=True).
- **P7** CSV-join evidence attached to the wrong file
  - Repro: mri-pairedfield-four-field-strengths: availability.tsv has modality=T1W for all rows, but sampled files are *_T2W_3T.nii.gz; the report shows evidence 'csv:files/availability.tsv:modality=T1W' for T2W files (join keyed per source dataset/volume, not per file). Harmless here because registry labels are hard; would be wrong for modality-mixed datasets.
- **P8** Per-image coordinate CSVs are profiled as metadata tables
  - Repro: deepspot-smfish-simulated: 1999 files train/csv/N.csv (numeric spot coordinates) each become a table with columns '124','2',... -> ~4000 junk columns in profile.json. load_tables should skip tables whose key column match score is low or whose header row looks numeric (header cells that are numbers). Same for skin-lesion-yolo-seg-4class: 7000 YOLO .txt label files (extension .txt is read by load_tables) become 7000 tables of numeric columns.
- **P9** Kaggle lister silently caps at 50,001 files
  - Repro: download.list_kaggle('nih-chest-xrays/data') -> listed_files 50001 of 112k; only images_001..006 of 12 shards are ever sampled. Also slug typo returns HTTP 403 (nih-chest-xray/data) -> state manual.
- **P10** DICOM derived reformats and body-part keyword 'torso'

- **P14** cmd_map crashes when profile produced no samples (no metalabel dir); validate drops the download record on any exception

In validate.py the report for an exception contains only status+trace, so the download state (what was fetched) is lost.
- **P15** extract_archives ignores archives in subfolders (Dataverse directoryLabel)
  - Repro: bosque-test-set: list_dataverse returns name 'BOSQUE_test_set/BOSQUE_test_set.zip'; download stores archives/BOSQUE_test_set/BOSQUE_test_set.zip; prepare.extract_archives iterates (root/'archives').glob('*') -> sees the directory, zipfile.is_zipfile(dir) -> [Errno 21] Is a directory, writes extracted/BOSQUE_test_set.err and 'no media found'. - **P16** fetch_entries 'whole' archive branch assumes one archive satisfies the whole quota

- **P21** Multichannel 16-bit TIFF normalised jointly across channels -> blank images (all 140 dropped)
  - Repro: eph4-cdk2-cdk4-reporter-nuclei-2026 (zenodo 19500864, Dataset_Zenodo/tiff_files/A_1_0.tiff = 1040x1392x4 uint16): channel means 1948 / 89 / 302 / 507 (channel 0 is a flat offset). prepare.to_pil keeps channels 0..2 and to_uint8 uses ONE percentile window over all of them, so the resulting RGB has std 5.1 and informative() returns False -> 'blank_or_tiny: 140', state 'empty'. - **P22** Multi-token metadata values keep only the first class
