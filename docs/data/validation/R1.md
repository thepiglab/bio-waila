## Remaining pipeline bugs (minimal reproductions)

1. **PIL silently mis-decodes 16-bit multi-sample TIFFs (eph4-cdk2-cdk4-reporter-nuclei-2026 still gives 0 images).** `prepare.read_image` opens with PIL first; for a 1040x1392x4 uint16 TIFF `Image.open(p).mode == 'RGBA'` and `np.array(im).max() == 15` (truncated to 8 bit), no exception, so the tifffile fallback never runs and `informative()` rejects the near-black image. Repro: zenodo 19500864, `Dataset_Zenodo/tiff_files/A_1_0.tiff` (11.6 MB via remotezip); `tifffile.imread` max is 4095 and `to_pil()` of it is informative. Fix: for .tif/.tiff (or BitsPerSample tag > 8) use tifffile first.

2. **NIfTI axial rule yields squashed strips for non-axial or cropped volumes (hvsmr-2-0 8/8, verse-2019 2/8).** hvsmr-2-0 `orig/pat4_orig.nii.gz` (figshare 25226360): raw shape (256,209,140), zooms (1.055,1.055,0.65), axcodes PIR (sagittal acquisition, 91 mm LR slab). After `as_closest_canonical` axial slices are 140x256 px with 0.65x1.05 mm pixels and are saved without spacing correction (outputs such as 110x480, 120x512). Fix: slice along the native acquisition axis unless near-axial, and/or resample to square pixels with the header zooms, and skip slices with aspect > 3.

3. **HF streaming sample is biased to the head of an ordered dataset (pannuke: 140/140 rows are Breast).** `download.py` ~line 549: `dsd[sp].shuffle(seed, buffer_size=100)` then take(n). PanNuke is stored sorted by tissue so a buffer of 100 gives one organ (hf:tissue='Breast' for every sampled row), which also biases the production sample. Fix: sample evenly spaced row groups/rows (`ds.skip`/stride) instead of a small shuffle buffer.

4. **dataverse.no rate-limits ranged zip reads (captiv8 'download error 403').** `download.sample_zip_remote` extracts members one request each; against `https://dataverse.no/api/access/datafile/196626` the 36th request within ~17 s returns 403 (a request 10 s later returns 206), so the whole dataset errors. Repro: `sample_zip_remote(Entry('Frames_and_videos.zip',3951201762,url), tmp, 42, 0, [], budget=2e9)`. Fix: retry with 20 s backoff (up to 5x) around `z.extract` and ~1 s between members. Verified by monkeypatching `RemoteZip.extract` (sleep 1.5 s + retry): 30 images.

5. **Whole-zip strategy has no retry/resume (cisd-urine-cytology-2022).** max-gb 2 selects strategy 'whole' for a 1.89 GB zip; `ChunkedEncodingError: IncompleteRead(1336865652 bytes read, 552016474 more expected)` aborts the dataset. With `--max-gb 1.5` the zip-range path needs 4 MB. Fix: resume with `Range` on IncompleteRead, or prefer zip-range above ~500 MB.

6. **`waila-metalabel map` crashes on a fresh worker folder when the first dataset has no media/profile (behsof-nafld-us).** `uv run waila-validate --only behsof-nafld-us --worker NEW` -> `OSError: Cannot save file into a non-existent directory: .../work/NEW/metalabel` at `cmd_map` (`pd.DataFrame(vm_rows).to_csv(out/'metalabel'/'value_map.csv')`). Fix: `mkdir(parents=True, exist_ok=True)` in cmd_map/cmd_apply.

7. **Direct-URL entries are typed by the last URL segment (OPARA DSpace 7: appendix300, d4d).** `list_direct` names the entry `content` for `.../bitstreams/<id>/content`, so no zip/tar logic applies ('only 1 loose media files listed, budget limits to 0 files'). Using the legacy `https://opara.zih.tu-dresden.de/bitstream/handle/123456789/<handle>/<file>` URL (redirects, supports Range) keeps the file name and works (routes in the JSON above). Also unsupported: a `doi` route to opara.zih.tu-dresden.de (state manual). `Appendix300_Images.zip` is not usable: 330 stored nested `frames.zip` (~380 MB each) that `sample_zip_remote` cannot descend into.

8. **Content-based mask filter misses instance-label images (mitoem).** `looks_like_mask` needs <=4 distinct grey levels or two levels covering >=98%; mitoem `seg*.tif` (sparse blobs on 0 with dozens of grey ids) pass, so 8/8 samples were label maps labelled 'scanning electron microscopy'. Suggest: >=90% of pixels exactly 0 and the nonzero pixels having few distinct values per connected blob, or file-name prefix seg/label.

9. **`informative()` passes featureless frames (real-colon S0/S2/S5, near-uniform red).** std > 6 and >5% pixels > 10 holds for a smooth red gradient. Suggest a gradient-energy test for endoscopy.

10. **exclude_paths is not applied by metalabel profile.** profile counts excluded files (aroma 7306 vs 843 media; murine 1054 json columns from annotations_labelme; lfa1 analysis_output names). Harmless to labels but slow and makes `path:name` stats misleading.

11. **Zenodo `Dataset 3`-style derived copies pass `is_mask` (prostate-ppat-healthy-longitudinal-2026).** `Dataset 3.zip` holds float64 gland-masked, normalised volumes (160x160x96, only ~4.5% of voxels > 0); every slice fails `informative()` (std 40, 4.5% > 10) so the dataset gives 0 images. Needs exclude_paths 'Dataset 3' (in the JSON above); a derived-volume check is not feasible generically.

12. **Slice sampling of CT includes thorax-level slices and mirrors burned-in text (trusted-3dus-ct-kidney, msd-task07-pancreas).** Central 30-70% of z for abdominal volumes returns lung/heart slices labelled kidney/pancreas; 3D-US volumes show mirrored GUI text after canonical orientation + rot90.

13. **Column-name regex noise in review lists (m4raw-abdomen, real-colon, mm-mcd).** `acqui*`, `sequence` and a server-path column are proposed as submodality/body_part review values; nothing is applied.

14. **Harness note.** Running the same dataset twice concurrently under one worker name races on `raw/<id>` (my cisd run produced a spurious FileNotFoundError on `_status.json` for that reason); the reports for appendix300, d4d, mouse-rvo, mcoa, prostate, lfa1 and viralskin in data/cache/reports are from the temporary-plan test runs (worker r1x), i.e. they show the proposed fixes applied.

## Cache and disk

`uv run waila-cache status` was checked before every batch and repeatedly during runs (other agents r2-r4 shared the cache): cache peaked at about 5.8 GB of the 20 GB cap and disk free never fell below about 15 GB (>= 8 GB required); final state 2.0 GB cache, 21.4 GB free. `--keep-raw` was never used and every raw sample was deleted by the harness. Temporary scratch files (about 50 MB) were kept outside data/. No software was installed; RAR (aattct-ids, renji-esd-esophagus) and OpenSlide (bracs) datasets are reported as blocked-local.
