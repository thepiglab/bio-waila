## Remaining pipeline bugs (with minimal reproductions)

1. **Overrides are ignored for 0/1 indicator columns** (btxrd). In `cmd_map` (src/bio_waila/data/metalabel.py) the branch `if set(values) <= {"0","1",...}:` maps the column name through `match_value` and then `continue`s without ever consulting `ov`. Repro: `uv run waila-validate --only btxrd --worker x --pilot 100 --max-gb 2 --redo`, then `grep btxrd work/x/metalabel/value_map.csv`: hand/foot/hip/knee are mapped by method `indicator` to `hand`/`foot`/`hip`/`knee`, none of which is in the registry candidate set {lower limbs, pelvis, upper limbs}, so body_part stays candidates for 90% (hard only for `pelvis`). The 15 rows in plan/overrides.csv (e.g. `btxrd,csv:...dataset.xlsx:hand,1,body_part,upper limbs`) are never used. Fix: look up `(did, col, "1")` (and wildcards) in `ov` first in that branch. humerus/radius/ulna/tibia/fibula/femur/wrist-joint columns get no mapping at all for the same reason.
2. **An override for one field suppresses automatic matching of the other fields for that value** (cystods). In `cmd_map`, `if key_ov: ... continue` skips `match_value`/DICOM code mapping for all fields. Repro: `uv run waila-validate --only cystods ...`: with only `cystods,*,WLC,modality,endoscopy` the auto mapping WLC -> submodality `white-light endoscopy` (91% hard in V1) vanished; submodality is now masked on 100%. Workaround: the explicit submodality row above; fix: only `continue` for the fields that have override rows.
3. **tar-stream samples the first N members, not a spread** (cross-choleact): 18 mp4 clips (3.5 MB), all from CholeCANE_09, 100 near-identical frames. Repro: `--only cross-choleact`.
4. **zip-range .mhd without its data file** (shoulder-3d-us-mosaicking): 70 members, 17,937 bytes, all `.mhd` headers; `reader_error:RuntimeError` on all, 0 images. The sidecar (ElementDataFile .raw/.zraw) is not fetched in the zip-range path. Repro: `--only shoulder-3d-us-mosaicking`.
5. **Unsupported zip compression** (ispy2): `NotImplementedError: That compression method is not supported` (Deflate64/zstd) on the 9.4 GB zip; nothing downloaded. Repro: `--only ispy2`.
6. **Missing download routes**: BioStudies/BioImage Archive (biad2493-two-channel-tirf-colocalization, oi-dic-smlm-correlative-biad3889: `GET https://www.ebi.ac.uk/biostudies/api/v1/studies/<acc>/info` returns `httpLink` https://ftp.ebi.ac.uk/biostudies/fire/S-BIAD/<last3>/<acc>) and ISIC archive API (isic-clonal-sk).
7. **TiffFileError on 40 files** (partaker-ecoli-phase-benchmark): all `co-culture-2/frames/train_P*_T*.tif` (40 of the 80 files of that folder; co-culture-1 decodes). Raw data was deleted after the run; repro: `--only partaker-ecoli-phase-benchmark --keep-raw` then `tifffile.imread` on `train_P3_T0167.tif` (I did not use --keep-raw as instructed).
8. **Byte budget still exceeded** with `--max-gb 2`: mitoem-2 5.06 GB reported (raw 3.3 GB on disk), magic-ct 3.16 GB (zip-range counts compressed size of ~100 MB nrrd members), recist-ct-hcuch 2.10 GB, ir-pupil 1.85 GB (ok), fetal-planes-db 2.09 GB (single 2 GB zip).
9. **Purely numeric file-name tokens are dropped** (virtual-staining-caco2-viability): `6.0.jpg` (transmitted light) vs `6.1.jpg` (fluorescence) never become a `path:name` column, so the dye override from the folder name is applied to both kinds (about half the images get a wrong stain). Repro: `--only virtual-staining-caco2-viability`; the profile has only `path:d1`.
10. **exclude_paths is not applied to files that come out of a whole-downloaded archive** (drends): the small whole zip was fetched and its mp4s extracted, then prepare removed them all (`no media found`); the exclusion only filters zip-range listings. Minor, but it wastes the download.
11. **Generic DICOM `Modality=CT` is a strong submodality claim** (head-cta-intracranial-aneurysm-dicom-2025): `dicom-code` maps CT -> `conventional ct`, which conflicts with the registry's `spiral ct` on 33/33 images (logged as conflicts). Noise, but it hides real conflicts; `DICOM_MODALITY['CT']` should give no submodality.
12. Cosmetic: cellfmcount loads 2,506 per-image `ground_truth/*.csv` files as profile tables (thousands of high-cardinality X/Y columns); slow, harmless.
13. Whole-body or multi-region volumes cannot be labelled per slice from study-level DICOM tags (ct-lymph-nodes: ABDOMEN/MEDIASTINUM series run neck to pelvis; head-cta: NECK/HEAD series run chest to vertex); registry `multi` labels (above) are the workaround.
